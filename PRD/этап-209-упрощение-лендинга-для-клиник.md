# PRD — Этап 209: Упрощение лендинга для клиник

## Контекст и цель

Лендинг одновременно объясняет продукт сотруднику клиники и техническому
специалисту. Для ветврачей и администраторов ранние технические термины мешают
понять главный сценарий: подключить Vetmanager и задать вопрос привычному
ИИ-помощнику.

Цель: сделать первый экран и основной путь понятными нетехнической аудитории,
не меняя регистрацию, интеграции, OAuth, хранение или MCP runtime.

## Scope

1. Получить и принять UI/UX и copy-решение Claude Opus 5 для существующего
   server-rendered landing.
2. Упростить шапку, hero, раннее объяснение и нижний CTA; технический контент
   оставить в свёрнутом разделе для разработчиков либо footer.
3. Сделать trust-copy точным: логин и пароль Vetmanager не хранятся;
   зашифрованно хранится только минимально необходимый защищённый ключ
   подключения; бизнес-данные клиники (клиенты, пациенты, записи и платежи)
   не сохраняются.
4. Оставить общий CTA «Подключить за 2 минуты» прямой ссылкой на `/register`;
   карточки ChatGPT, Claude и Manus — необязательный выбор.
5. Обновить unit/browser regression tests, проверить 375px и desktop, затем
   deploy и production smoke публичных страниц.

## Не в scope

- Новые помощники, интеграции или изменение их протоколов.
- Изменения OAuth, account registration, storage, telemetry, API/MCP runtime.
- A/B-тесты, аналитические события, миграции или редизайн кабинета.

## Принятое UI/UX-решение Claude Opus 5

Claude Opus 5 review `41732291-d2c7-4d6c-b54f-1b082e6b39cf` одобрил с
правками короткую структуру: шапка → hero и общий CTA → доверие → три шага →
помеченный пример ответа → необязательные карточки помощников → данные →
финальный CTA → footer/developer disclosure.

Принятые тексты:

- header: «Vetmanager для ИИ-помощника»;
- hero: «Ваш ИИ-помощник теперь знает вашу клинику»;
- hero lede: «Подключите Vetmanager к ИИ-помощнику, которым вы уже
  пользуетесь, и спрашивайте о записях, приёмах и выручке обычными словами.»;
- primary CTA: «Подключить за 2 минуты» → `/register`;
- trust: «Логин и пароль от Vetmanager не сохраняются», «Данные клиники не
  храним — берём их только чтобы ответить на ваш вопрос», «Подключение
  защищено и работает только для вашей клиники»;
- three steps: зарегистрироваться и подключить клинику → открыть привычный
  ChatGPT, Claude или Manus → спросить обычными словами;
- chat: «Пример ответа» и «Данные в примере вымышленные» без даты;
- privacy: login/password не хранятся, отдельный защищённый ключ подключения
  хранится зашифрованно, business data не сохраняются;
- final CTA: «Подключите клинику к своему ИИ-помощнику» / «Подключить» без
  второй оценки времени.

Принятые findings: убрать конфликт «2/5 минут», технические header/MCP,
противоречие privacy-copy и устаревшую дату. Карточки помощников переносятся
ниже примера и явно обозначаются необязательным вариантом. Опус предложил
только out-of-scope решения (новые экраны, assistants, analytics, experiments,
изменения регистрации и storage); они отклонены без изменений backend.

## Архитектурное решение

### Проблема и ограничения

`landing_page.py` рендерит landing на сервере; CTA и существующие ссылки на
`/register` — часть публичного web-поведения. Регистрация и account flow не
меняются. Тексты о privacy должны соответствовать storage contract: login и
password не хранятся, а connection token является секретом и не должен попасть
в HTML, тестовые артефакты или логи. На 375px элементы выбора и CTA должны
оставаться видимыми, иметь target не менее 44px и не создавать overflow.

### Варианты

1. Новый onboarding или выбор помощника перед регистрацией.
2. Точечно изменить server-rendered copy и существующую визуальную иерархию.
3. Оставить технический landing и добавить отдельную нетехническую страницу.

### Выбор и инварианты

Выбран вариант 2: один файл landing + его текущие тесты. Общая CTA остаётся
`/register`, поэтому будущие помощники не требуют изменения маршрута. Бренды
`ChatGPT`, `Claude`, `Manus` остаются именами карточек, а общая терминология —
«ИИ-помощник». Вне свёрнутого блока для разработчиков не показываются MCP,
OAuth, API, Bearer, token/scope и другие технические термины.

### Rollback

Один revert возвращает прошлые server-rendered тексты и стили. Регистрация,
данные аккаунтов, grants, ключи подключения и runtime остаются без изменений.

## Acceptance criteria

- Hero содержит ровно одну оценку времени — «2 минуты»; общий CTA ведёт на
  `/register` и не требует выбора помощника.
- В видимом нетехническом контенте используется «ИИ-помощник», а `Claude` не
  переводится; технические термины скрыты в developer disclosure.
- Chat явно обозначен «Пример ответа» и не содержит устаревшей даты.
- Видимые privacy-тексты точно описывают: login/password и business data не
  хранятся; только защищённый ключ подключения хранится зашифрованно без
  раскрытия его значения.
- Каждое privacy-утверждение имеет проверенную опору: `storage_models.py`
  хранит connection payload только в `encrypted_credentials`; login/password
  flow передаёт их только в `save_user_login_password_connection()` и сохраняет
  user token; `tests/test_web_auth.py` и
  `tests/test_browser_happy_path_user_token.py` подтверждают отсутствие
  password/token в storage plaintext и HTML.
- Unit tests и browser tests проверяют copy, CTA targets, 375px/desktop и
  отсутствие горизонтального overflow; полный Docker suite и production smoke
  GET-only `/`, `/register`, `/healthz`, `/readyz` проходят без создания
  аккаунта и без записи user data в output.
- Технические термины проверяются структурно: они отсутствуют вне subtree
  закрытого `#mcp-agent-instructions`; существующие `#chatgpt-connector` и
  `#mcp-agent-instructions` anchors сохраняются для внутренних ссылок.
- В нижнем второстепенном блоке сохранена ссылка на Open Source-проект и
  короткая информация для технической команды о самостоятельной установке на
  своём сервере. Это не конкурирует с CTA подключения клиники.

## Review gates

Architecture Critique: not required. Задача меняет только server-rendered copy
и layout существующего public landing; регистрация, auth, storage, public API,
MCP and runtime contracts не меняются. UI/UX decision Claude Opus 5,
Spark/strong PRD review и committed-diff reviews обязательны по workflow.

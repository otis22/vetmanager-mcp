# Этап 479. Количества Report AI без ложной маски телефона

## Цель

Отдельным поездом исправить локальную ложную замену числовых агрегатов количества в строках Report AI при сохранении маскировки настоящих контактных данных. Этап 480 остаётся `supervisor_pending`; очистка имени не меняется.

## Evidence и граница

Read-only проверка 19.11.2026 на существующем отчёте исходного подключения #156: прямой ВМ вернул 1097 строк без масок телефона; MCP на тех же строках вернул 104 маски в колонках, обозначающих количество. Исходный job обращения не сохранён, поэтому совпадение с ним не утверждается. Значения и названия колонок в публичный evidence не переносились. Класс локального преобразования подтверждён, бизнес-семантика каждой маскированной ячейки ещё требует типовой проверки.

## План и обязательные сторожа

1. Сопоставить типы колонок и исходные числовые значения на разрешённом контуре, без ПД в фикстурах.
2. Сначала показать красный сторож для агрегата и отдельный красный сторож для маскировки реального телефона; зафиксировать, чем сломан каждый. Затем минимально изменить очистку.
3. Проверить JSON и CSV, все слои деперсонализации, живой изменённый инструмент на стенде и обязательные гейты workflow.

## Архитектурное решение

`get_report_ai_job_data` отдаёт строки отчёта через `sanitize_tool_result`; CSV
очищается через `sanitize_report_cell`. Оба пути уже сохраняют строгое
`Количество` и фиксированные десятичные суммы, но заголовок вида
`Количество услуг` не входит в узкое исключение. Подтверждённый контракт
тестового REST-ответа: `columns` — строки, значения строк могут быть числами;
метаданных о типе или происхождении колонки в ответе нет. Поэтому исключение
можно расширять только для целой числовой ячейки с проверенным форматом и
количественным заголовком без маркеров телефона/идентификатора. Свободный
текст, смешанные значения, preview и неразмеченные поля продолжают проходить
общую очистку. JSON и CSV используют одну проверку ячейки.

Приёмка: строковая ячейка целиком совпадает с форматом: от 1 до 9 цифр
целой части (или 1–3 цифры и одна-две группы по три цифры с пробелом,
NBSP U+00A0 или узким NBSP U+202F),
затем точка или запятая, ровно две произвольные цифры и ровно восемь нулей.
Знак, экспонента, лишние пробелы и другие дробные разряды не допускаются.
Исключение действует для заголовка с отдельным словом
`Количество`/`count`/`qty` после `casefold`; словом считается последовательность
букв/цифр между пробелами, подчёркиваниями или знаками препинания. Оно не
срабатывает внутри `account` или `discount`. Колонка должна проходить
`report_numeric_columns`: его текущий запрет на телефон, phone, код, code,
артикул, article, sku, barcode, ean, gtin, isbn, serial, номер, uuid и ID
остаётся. Дополнительно исключены `контакт`, `контактов`, `contact`, `contacts`,
`идентификатор`, `идентификаторов`, `identifier`, `identifiers`, `карта`,
`карте`, `карт`, `card`, `cards`, а также по privacy review — `client`,
`clients`, `owner`, `owners`, `клиент`, `клиента`, `клиентов`, `владелец`,
`владельца`, `владельцев`, `хозяин`, `хозяина`, `хозяев`. Иные сокращения и
переводы не добавляются. Уже
разрешённое строгое `Количество` сохраняет прежний контракт для целого
10–11-значного значения с известным остаточным риском из этапа 368; новый
этап не расширяет это исключение. В `Телефон`, `Значение`,
`Количество телефонов`, смешанном тексте, preview и полях без заголовка
маскирование остаётся. Сторожа JSON/CSV должны доказать обе стороны.
Числовой JSON-тип остаётся числом по старому поведению; новые десятичные
нули не восстанавливаются из `int`/`float`. CSV очищает текст ячеек по тому
же правилу, которое JSON применяет к строковой ячейке. Preview не получает
исключение.
Альтернатива — разрешать любое число по слову «количество» — расширила бы
утечку голого телефонного номера; ожидание недоступной типизации не исправит
подтверждённые фиксированные десятичные ячейки. При провале privacy-сторожа
или live проверки исключение откатывается до прежнего поведения.

Изменение границы исходящих данных требует Architecture Critique совместно
с PRD-review до реализации.

## Вне объёма

В этом документе нет разрешения менять production, запускать новый Report AI job или ослаблять очистку для неразмеченных/контактных колонок. Для живой проверки выбирать разрешённый стенд до запуска; retry существующего `file_id` не создаёт новый job.

## Выпускное решение владельца, 19.11.2026

Выпустить 479 отдельным поездом после всех оставшихся real групп на devtr6,
с явным исключением только
`tests/test_stage420_live.py::test_stage420_live_dedup_repeated_intent`.
Красный raw shard сохраняется: старый matched-отчёт возвращает 0 строк,
seed — 12 строк с zero-fill. Это upstream semantic match, эскалированный в
ВМ; не считать его зелёным тестом и не менять oracle для выпуска. Этап 483
остаётся `supervisor_pending`, локальная fail-closed проверка пригодности
matched-отчёта планируется в 484. Маска имени 480 не меняется.

# Этап 254. Документация без Deploy Prod

## Цель

Не пересоздавать production-контейнер после коммита, который меняет только
документацию и управленческие артефакты, сохранив деплой следующего коммита с
кодом после успешного `Tests` на `main`.

## Архитектурное решение

`Deploy Prod` остаётся workflow, запускаемым `workflow_run` после успешного
`Tests` с `head_branch == 'main'`. Перед deploy добавляется отдельный job,
который checkout'ит именно `workflow_run.head_sha`, сравнивает его с родителем
и выдаёт `should_deploy`. Документационные пути (`*.md`, `PRD/`, `docs/`)
сами по себе дают false; изменение любого прочего пути даёт true. Это проще,
чем дублировать `Tests` или менять триггер workflow_run, и не связывает два
последовательных запуска: каждый event использует свой immutable `head_sha`.

Инварианты: успешный Tests кода на main по-прежнему запускает Deploy; secrets
доступны только deploy-job; doc-only run не запускает remote commands.
Rollback: удалить prepare-job и его `if`, восстановив прежний единственный job.

## Декомпозиция

1. Добавить detect-job и condition deploy-job, ≤100 LOC.
2. Добавить статические регрессии для workflow, ≤100 LOC.
3. Проверить YAML и полный контейнерный suite.

Architecture Critique: required (production deployment behavior).

## Acceptance criteria

- Doc-only diff не выполняет deploy-job.
- Python/config/Docker/runtime diff выполняет deploy-job.
- Условие success + `head_branch == 'main'` остаётся на пути к deploy.
- Следующий code commit независимо вычисляется из своего `head_sha`.

# Этап 221. Клиническая глубина профиля пациента для демо

## Цель

К 20.08.2026 сделать `get_pet_profile` достаточным источником проверяемой
клинической истории пациента для врачебного демо: история не должна молча
обрезаться на пяти последних картах, а диагнозы не должны оставаться числовыми
идентификаторами. Поиск пациента по кличке должен дать агенту безопасный путь
получить `pet_id`, не вынуждая угадывать владельца.

## Подтверждённые факты

- На test contour `devslon67` у Муси (`pet_id=740`) API
  `GET /rest/api/MedicalCards` с filter `patient_id=740` вернул `totalCount=7`.
  Текущий профиль запрашивает `limit=5`, поэтому исключает карты от
  2024-09-12 (вес 5,2; креатинин 168) и 2024-12-19.
- В тех же картах `diagnos` равен строковому ID `124`, а `diagnos_text` пуст.
  `GET /rest/api/MedicalCards/AllDiagnoses` — подтверждённый справочный
  endpoint (OpenAPI/reference); его title нужен для клинической выдачи.
- API возвращает structured `weight`, но креатинин находится только в
  свободном тексте `description`. Сервер не может надёжно приписать единицы,
  анализ или клинический смысл числу регулярным выражением.
- `get_pets(alias="Муся")` намеренно отклоняется без `owner_id`; одному
  вопросу врача неоткуда получить этот ID.
- Для несуществующего `pet_id` upstream возвращает успешный пустой envelope,
  поэтому агрегатор обязан превратить его в явное not-found состояние.

## Scope

### 221.1 Исследование и решение

Зафиксировать реальные вызовы и недостающие данные для шести вопросов демо,
включая профили Персика (744), Ники (746), Тимоши (748), и пройти PRD review.

### 221.2 Клиническая история профиля

1. Запрашивать до 100 последних MedicalCards, сортированных `id DESC`.
2. Возвращать `medical_cards_total`, `medical_cards_returned` и
   `medical_cards_truncated`; полный ответ не должен выглядеть как полный при
   превышении лимита.
3. Один раз за профиль получать AllDiagnoses отдельным reference limit,
   сопоставлять scalar `diagnos`
   и элементы `diagnoses` с `id`, добавляя клинически удобное поле
   `diagnosis_titles` к каждой карте и top-level `diagnoses` без удаления
   исходных upstream-полей.
4. Если pet endpoint вернул не object с положительным `id`, вернуть
   `NotFoundError`; не делать следующие fan-out запросы.

### 221.3 Поиск по кличке

Добавить отдельный read-only `find_pets_by_alias(alias, limit, offset)`: exact
case-insensitive/partial matching остаётся upstream LIKE semantics, но ответ
проецируется только на `id`, `alias`, type/breed/birthday/status и pagination
metadata. Он не раскрывает owner/client fields. Если совпадений несколько,
`totalCount` и `has_more` требуют от модели выбрать пациента по контексту или
задать уточнение. Существующий `get_pets` и его требование `owner_id` не
меняются.

## Вне scope до вебинара

- NLP/regex извлечение креатинина, IRIS-стадии, назначений или дат контроля из
  `description`/`recomendation`: это создаёт ложную клиническую точность.
- Новый диагноз/лечение, интерпретация тренда и clinical decision support.
- Новые агрегаторы для недельных приёмов и неявившихся, сгруппированных по
  врачу: это отдельные аналитические контракты и не должно маскироваться
  профилем пациента.
- Изменение существующего raw `get_pets` privacy/ambiguity contract.

## Архитектурное решение

### Проблема и граница ответственности

Профиль — server-side агрегатор известных API-сущностей. Сервер обязан
сохранить полноту, pagination facts, идентичность и deterministic dictionary
joins: это факты, для которых модели нельзя безопасно догадываться. Модель
читает врачебный свободный текст и формулирует ответ; она не является источником
данных, но лучше подходит для связного резюме без придумывания клинических
значений.

### Контекст и ограничения

Сохраняются current FastMCP/tool patterns, `gather_sections` partial contract,
read scopes and global privacy wrapper. `MedicalCards` и `AllDiagnoses` read
endpoints подтверждены artifacts/OpenAPI и real contour. Дополнительный
справочник — один bounded request; карты ограничены 100, чтобы не превратить
один вопрос в неограниченную выгрузку. Публичный MCP contract расширяется
additively; `last_medical_cards` остаётся для обратной совместимости.

### Варианты

1. Оставить пять raw-карт и дать модели запросить страницы самостоятельно.
   Неприемлемо: модель не видит молчаливой обрезки и может ответить уверенно
   неполно.
2. Извлекать все показатели и клинические события regex-ами на сервере.
   Неприемлемо: лабораторные значения и их смысл находятся в свободном тексте,
   поэтому silent false positives опаснее отсутствующей сводки.
3. Bounded history + explicit completeness + deterministic diagnosis join.
   Выбрано: решает доказанные дефекты, мало меняет contract и сохраняет
   клиническую интерпретацию за человеком/моделью.

### Инварианты

- Raw upstream cards не переименовываются и не удаляются.
- При `medical_cards_truncated=true` total/returned позволяют модели честно
  сообщить ограничение.
- Никаких owner/client полей в новом alias-search response.
- Пустой pet response — ошибка not found, не success с пустым profile.
- Ошибка diagnosis lookup оставляет profile usable и фиксируется в
  `section_errors`, а не уничтожает историю.

### Rollback/fallback

Если AllDiagnoses меняет envelope или недоступен, returned cards сохраняются,
`diagnosis_titles` пусты, а partial error маркируется. Endpoint не отдаёт
`totalCount`; поэтому profile всегда явно сообщает unknown completeness
справочника и IDs без title, а не маскирует их пустым title. Если нагрузка/размер
ответа 100 карт окажется неприемлемым, rollback — уменьшить named constant,
сохранив обязательные total/truncated metadata. Новый alias tool можно снять из
регистрации без изменения старого `get_pets` contract.

## Подзадачи

1. ≤150 LOC: fetch clinical cards/diagnosis dictionary и добавить metadata.
2. ≤150 LOC: explicit not-found и новый минимальный alias-search tool.
3. ≤150 LOC: mock regressions для полноты, join, lookup failure, not-found,
   ambiguity/privacy; real smoke для фиксированных demo patients.
4. ≤150 LOC: audit, Docker checks, real contour, reviews, commit/push.

## Acceptance criteria

- Муся возвращает 7/7 карт, `medical_cards_truncated=false`, титул диагноза и
  обе ранние точки веса/креатинина в source text.
- Персик, Ника и Тимоша получают titles вместо только IDs.
- Неизвестный pet_id выдаёт explicit not-found error.
- Alias search выдаёт candidate `id=740` без owner data и сообщает ambiguity.
- Existing mock suite, full Docker suite и opt-in real contour с devslon67
  проходят; никакие секреты не пишутся в files/output.

## Architecture Critique

Required: меняется публичный MCP contract, upstream fan-out и privacy boundary
нового инструмента.

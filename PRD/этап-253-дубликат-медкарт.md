# Этап 253. Список медкарт приезжает дважды

## Цель

Убрать созданный нашим кодом дубликат списка `medicalCards`/`medicalcards` из
ответа `get_medical_cards`, сохранив корректную обработку документированного
upstream ключа и безопасный read-path для старых вариантов ответа.

## Проверенные факты

- `GET /rest/api/medicalCards?limit=2` на devtr6 возвращает в `data` только
  `totalCount` и `medicalCards`.
- Строки 97–98 `tools/medical_card.py` добавляют `medicalcards` как тот же
  объект списка; upstream этот второй ключ не присылает.
- Alias добавлен в коммите endpoint migration `ef446dd`; он был defensive
  compatibility workaround. Внутренние read-paths используют fallback для
  разных вариантов, а `update_medical_card` намеренно вызывает
  `unwrap_single_record(..., "medicalCards")`.
- Поиск присваиваний ключей в `tools/` показывает, что это единственный
  list-response alias. `medicalcards` у vaccinations — отдельный upstream
  endpoint и не является дубликатом основного списка карт.

## Scope

1. Перестать добавлять alias в публичный ответ `get_medical_cards`.
2. Оставить fallback reads только там, где они читают ответ upstream, не
   переписывая его.
3. Обновить mock regression: единственный canonical ключ проходит к MCP
   клиенту, а отсутствующий lowercase key не создаётся.

## Архитектурное решение

Проблема: outbound normalization удваивает payload и меняет публичный
контракт, хотя upstream на нужном endpoint уже canonical. Варианты: оставить
оба ключа; заменить canonical ключ на lowercase; перестать записывать alias,
но сохранить fallback чтение. Выбран третий: `medicalCards` подтверждён
endpoint contract и нужен `unwrap_single_record`, а fallback не несёт лишние
данные в ответе.

Инварианты: public list response содержит upstream records ровно один раз;
`update_medical_card` продолжает unwrap по `medicalCards`; специализированный
vaccination endpoint не меняется. Rollback — вернуть только прежнее
присваивание alias, если реальный compatibility client докажет зависимость;
никакая миграция данных не нужна.

## Декомпозиция

1. Заменить мутирующую нормализацию и добавить regression (≤150 строк).
2. Проверить остальные list tools статическим поиском (≤150 строк).
3. Выполнить полный test contour, аудит и review.

## Acceptance criteria

- `get_medical_cards` возвращает `data.medicalCards` без
  `data.medicalcards`, если upstream прислал только canonical key.
- Внутренние fallback reads и `update_medical_card` не регрессируют.
- Поиск остальных list tools не находит аналогичного alias mutation.

# Этап 430 — мягкий парсинг JSON-строковых параметров

Дата: 21.10.2026. Источник: Sentry 7795893973, 13 ошибок `list_type` у `get_clients` за 14 дней.

## Цель и факты

Публичные MCP-инструменты принимают структурные аргументы как JSON-значения. Агент иногда сериализует массив или объект ещё раз и посылает строку. Pydantic отклоняет вызов до исполнения инструмента. В `tools/` публичные `filter`/`sort` имеют тип `list[dict]`; другие массивы включают `diagnosis_ids`, `good_ids`, `params_shape`. Форма REST-фильтра по контракту: массив объектов с `property`, `value`, `operator`. Существующая проверка допустимых полей и прав сохраняется после парсинга.
`artifacts/technical-requirements-vetmanager-mcp-ru.md` § MCP tools подтверждает, что type hints/docstring формируют MCP schema и что list GET использует общий `sort/filter`; § FilterBuilder закрепляет `filters.py` как общий модуль сборки фильтров. OpenAPI v6 содержит `/rest/api/client` и `/rest/api/breed`; endpoint или формат запроса на REST-слое этап не меняет. Красный тест на установленной версии FastMCP подтвердил отсутствие автоматического pre-parse перед Pydantic.

## Декомпозиция

## Архитектурное решение

Проблема: двойная JSON-сериализация нарушает тип аргумента до запуска инструмента. Общий `BeforeValidator` в `filters.py` парсит **только строки**, если они содержат корректный JSON требуемой формы; обычные list/dict передаются без изменений. Алиас обязательного массива — `Annotated[list[T], BeforeValidator(...)]`, необязательного — `Annotated[list[T] | None, BeforeValidator(...)]`: валидатор снаружи union позволяет строке `"null"` стать `None`. Алиасы `FilterList` и типы иных структурных параметров используют его на границе Pydantic/FastMCP. Текст нашего исключения даёт короткий пример JSON и не дублирует исходную строку; FastMCP/Pydantic отдельно включает `input_value` в стандартный `ValidationError`, что уже происходит до исправления. Очистка стандартного сообщения требует отдельного изменения FastMCP boundary и вне scope этапа. Форма исходного массива/объекта проверяется Pydantic; скаляр после `json.loads` отклоняется. Пустая строка ошибочна; строка `"null"` для необязательного структурного параметра преобразуется в `None`, для обязательного — ошибочна. Явный JSON `null` в аргументе MCP и пропуск необязательного параметра сохраняют значение `None`. `"[]"` валидно для массива и означает пустой массив. Сами структурные параметры никогда не принимали строку как допустимое значение; поэтому JSON-строка, разбираемая как нужная форма, не имеет прежнего альтернативного смысла.

Альтернатива: обёртка вокруг регистрации всех tools. Она добавляет обходную точку входа, может расходиться с JSON schema и проверкой прав. Явная типовая аннотация сохраняет контракт на уровне FastMCP и ограничивает преобразование структурными аргументами. Не применять парсинг ко всем строкам: свободный текст может содержать JSON как текст. Инварианты: list/dict без изменений; неверная форма и malformed JSON не доходят до REST; существующие downstream validators продолжают работать; собственный текст ошибки не повторяет содержимое фильтра. Rollback: вернуть аннотации и валидатор вместе; legacy `list_type` восстановится без изменения REST-логики. Установленный FastMCP в test image не распарсил JSON-строку до `call[get_clients]`: красный прогон показал `list_type`. Если другая версия FastMCP умеет pre-parse, аннотация всё равно сохраняет то же наблюдаемое поведение.

Architecture Critique требуется: публичный MCP-контракт и production behavior меняются. Внешний контракт REST не меняется; область проверки — аргументы MCP.

## Acceptance

- Красные сторожа вызывают `get_clients` и другой tool с JSON-строкой и до исправления получают `ValidationError`; после исправления вызовы доходят до handler. Тестируют обычный список, пустую строку, `null`, `[]`, malformed JSON и неверную форму.
- Все публичные list/dict параметры охвачены общим валидатором; AST-инвентарь ловит голые inline аннотации, runtime инвентарь `mcp.list_tools()` проверяет развёрнутые алиасы и `BeforeValidator` в `Annotated` для каждого структурного параметра, включая добавляемые `fields`/`include`. Сторож показывается красным через возврат одной аннотации к `list[int] | None` или алиаса без валидатора. Отдельные проверки покрывают не-фильтровые массивы; объектных параметров в текущем публичном inventory нет. Описания `filter` прямо говорят «массив объектов, не строка».
- Живой `get_clients` на bearer-стенде devtr6 с JSON-строкой возвращает отфильтрованный ответ; контрольный вызов с массивом даёт тот же результат, а без фильтра — иной totalCount/набор. Код и тело в AssumptionLog.
- Spark → Astra и Opus для PRD/архитектуры и committed diff, аудит, mock и real suite по финальному SHA, CI зелёный, Roadmap/AssumptionLog завершены.

## Простота

Один валидатор для JSON-строк и несколько алиасов формы; без глобального middleware и без изменения REST-клиента.

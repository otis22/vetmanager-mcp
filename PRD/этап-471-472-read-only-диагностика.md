# Этапы 471 + 472. Read-only пострелизная проверка и catalog diagnostics

## Цель

Проверить выпущенные исправления по обращениям #150, #156, #160, #161, #168, #177 и обход #171–172, повторно исследовать #170, сравнить #173/#174 на одинаковых параметрах прямого API ВМ и MCP. Для каждого обращения передать обезличенное наблюдение, владельца `MCP`/`ВМ`/`integration`/`unknown` и следующее действие.

## Граница и факты

- Production и upstream доступны только на чтение. Не создавать Report AI/StartReport jobs и не менять состояния, включая feedback triage до доказанного результата.
- Для #177 использовать существующий сохранённый job/report из обращения; значения строк, названия номенклатуры и идентификаторы клиники в публичный репозиторий не переносить.
- Источник утверждений об API — `artifacts/vetmanager_openapi_v6.json` и `artifacts/api_entity_reference-ru.md`; реализация MCP и живые ответы — отдельные наблюдения.
- Исходные обращения в production `agent_feedback_reports` на старте: #150/#156/#160/#161/#168/#170/#173/#174/#177 `new`, #171/#172 `linked` к существующей проблеме; снимок 19.11.2026.
- Невозможность получить одинаковый контур, точные параметры или различающий свидетель обозначать `NOT_MEASURABLE`, не приписывать дефект компоненту.

## Подзадачи

1. **471.1** (≤2 ч): read-only снимок исходных reports и deploy; адресно повторить исправленные сценарии без сохранения сырых тел. Сопоставить наблюдение с заявкой и фиксировать границу проверки.
2. **471.2** (≤2 ч): #177 читать из существующего job; #170 проверить состояние существующего terminal failed и доступные признаки dedup без нового создания. Невозможность доказать переход после failed — отдельный вывод.
3. **472.1** (≤2 ч): #173/#174 — на одном подключении и с одинаковыми параметрами сравнить прямой ВМ и MCP; сохранить только код, форму и счётчики. При отсутствии такой пары — владелец `unknown`.
4. **472.2** (≤2 ч): для подтверждённого локального дефекта создать отдельный PRD и поезд без исправления здесь; для ВМ оформить безопасную эскалацию. Обновить Roadmap, AssumptionLog, внешний work log и handoff.

## Приёмка

- По каждому номеру есть обезличенное evidence с источником, временем, параметрами без чувствительных значений, результатом, владельцем и пределом вывода.
- #173/#174 получают владельца только по сопоставимой паре ответов или статический доказанный локальный дефект; иначе `unknown`.
- Нет production/upstream записи и новых Report AI/StartReport jobs; прямые ответы не обходят границы доступа.
- Изменения только документационные; пройти структурный checker, аудит diff и применимые docs-only gates workflow. Не закрывать feedback без подтверждения.

## Вне объёма

Исправления MCP и ВМ, deploy, новые тестовые данные, изменение публичных инструментов, массовые выгрузки и повторный запуск отчётов.

## Простота

Используются существующие read-only инструменты и один текстовый handoff. Новые runtime-абстракции и тесты не нужны.

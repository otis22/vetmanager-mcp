# Этап 354. Пустое превью Report AI и HTML медкарт

## Цель и проверенные факты

Репорты #108–#111: `ready_to_save` с `preview_summary` «0 строк» не
доказывает отсутствие данных: прямое чтение за тот же день вернуло карты.
Сохранённый отчёт может показать HTML из полей описания и рекомендаций как
разметку. Генерация запроса принадлежит Ветменеджеру; MCP отвечает за
подсказку агенту. Режим без персональных данных распространяется на сотрудников
и уже добавляет к интенту требование показывать идентификаторы вместо ФИО.
В локальном OpenAPI v6 нет `report-ai-job`; форма ответа подтверждена
`artifacts/report-ai-mcp-research-2026-06-15.md` и существующими тестами.
Живой devtr6 02.10.2026: POST задания за 01.01.1900 вернул HTTP 200,
GET вернул HTTP 200, `ready_to_save` и `Превью: 0 строк, 3 колонок`.

## Декомпозиция

- 354.1 (≤2 ч): PRD, источники, архитектурное и предметное ревью.
- 354.2 (≤150 строк): красные сторожа и подсказка при пустом превью,
  рекомендация для интентов по HTML медкартам.
- 354.3 (≤150 строк): условная подсказка про идентификатор врача при режиме
  без персональных данных и отрицательный сторож обычного режима.
- 354.4 (≤2 ч): живой devtr6, аудит, ревью, полный suite и выпуск.

## Архитектурное решение

**Проблема.** Агент принимает `ready_to_save` за подтверждение качества
отчёта и воспринимает идентификатор врача как ошибку.

**Контекст.** `get_report_ai_job` проходит через
`_annotate_report_ai_job_payload`; аналогичные советы размещены внутри `job`.
`preview_summary` — строка с числом строк, `preview_example_row` — выдуманный
пример структуры. Локальная настройка `is_depersonalized` доступна через
runtime credentials. Новые поля `job.mcp_empty_preview_guidance` и
`job.mcp_personal_data_guidance` добавляются без изменения старых полей;
возвращаемый `dict` не ограничен output schema. Подсказки не содержат
персональных данных. Никаких дополнительных REST-запросов в MCP.

**Варианты.** Только статический prompt не гарантирует, что агент его прочитает.
Блокировать `save` при пустом превью нельзя: пустота бывает корректной, а
согласие человека может быть вне MCP. Автоматически исправлять HTML/SQL в
отчёте нельзя без контракта конструктора. Выбран совет в ответе job при
нулевом превью, условный совет по режиму приватности и короткий текст helper.

**Инварианты.** Подсказка о нуле возникает только для `ready_to_save`, если
`preview_summary` начинается с `Превью: 0 строк` и далее содержит запятую с
числом колонок либо завершается; между словами допускаются пробелы. Число
строк разбирается целиком, так что `10 строк` и `0 строк из 10` не подходят.
Отсутствующий/непонятный `preview_summary` не считается нулём; различие
формата проверяет отдельный сторож с формой из живого devtr6-ответа. Неизвестный
формат не создаёт подсказку. Агент сверяет
исходные записи прямым чтением до сохранения,
не обещает рабочий отчёт и не сохраняет пустой без согласия человека. При
включённой деперсонализации (`is_depersonalized is True`) пояснение об
идентификаторе сотрудника есть; при выключенной, отсутствующей или неизвестной
настройке его нет. Режим приватности и требования к интенту не
ослабляются. Для медкарт helper просит учитывать HTML-пустоту и не выводить
сырой длинный HTML в отчёт.
Аннотация применяется и к повторно выданному `ready_to_save` в ответе create.

**Rollback.** Удалить только новые аннотации и строки helper, сохранив
старый payload и требование приватности. Ошибку SQL исправляет команда
Ветменеджера отдельно.

Architecture Critique required: меняется публичное поведение MCP и объяснение
приватности. Ревью покрывает также PRD целиком.

## Приёмка

1. `ready_to_save` с «0 строк» возвращает явно три действия: сверить прямым
   чтением, не считать отчёт рабочим, не сохранять без согласия человека.
2. Helper напоминает, что поля медкарт содержат HTML; `<div></div>` выглядит
   пустым, но может не проходить проверку пустоты; для вывода выбираются
   короткие признаки либо текст без разметки, когда это умеет конструктор.
3. Для обезличенного подключения объясняется ID врача как настройка клиники;
   обход и подстановка ФИО не предлагаются. Для обычного подключения этой
   подсказки нет. Сторожа на оба режима и отсутствующий флаг принимаются
   показанным красным.
4. Сторож helper проверяет фактический ответ MCP-инструмента на HTML,
   `<div></div>` и ограничение вывода сырой разметки; он показан красным.
5. На devtr6 задание с заведомо пустым результатом возвращает подсказку 1;
   наблюдённая форма `preview_summary` закреплена сторожем без данных клиники.
6. Полные проверки, ревью сторонней моделью, Tests и Deploy Prod зелёные.

## Простота

Без новой абстракции и запросов: аннотация в существующей функции и строки
в существующем helper. Одна точка для условий состояния job.

# Этап 390. Отказ и запасной режим свободных слотов

## Цель и приёмка

`get_doctor_free_slots` при строках без достоверного `ttype.is_working_hours` объясняет, сколько таких строк найдено, какие `type` и безопасные типовые `title` встречаются и почему расчёт невозможен. Произвольный `title`, который может содержать ПД, отображается как «скрытое название»; отказ советует посмотреть полное название через `get_timesheets`, проверить справочник `timesheet_types` и, если оператор подтвердил рабочее название, повторить запрос с `work_title`. Явно заданный `work_title` включает только строки с точным совпадением `title`, у которых отсутствует валидный дискриминатор. Остальные неизвестные строки перекрывают доступность как занятые интервалы. Строки с достоверным `is_working_hours=0` остаются исключёнными. Ответ с таким допущением содержит предупреждение о возможном завышении числа слотов. Неподходящий `work_title` не превращает неизвестное расписание в достоверный пустой результат.

## Проверенные факты

- Главный PRD требует композитных читающих инструментов; технические требования закрепляют Python/FastMCP. `api_entity_reference-ru.md` определяет поля `timesheet.type`, `title`, даты и `clinic_id`; OpenAPI v6 описывает REST list `/rest/api/timesheet/`.
- По проверке супервизора в vetmanager-extjs master `6fbabdc452`: реальный критерий `timesheet_types.is_working_hours=1`; `attach_timesheet_type=1` прикладывает `ttype` к REST list, этот параметр инструмент уже передаёт. В сидах type 2 и 6 рабочие, 3, 5, 7, 8 нерабочие; type 0 отсутствует. Справочник тенанта может отличаться, поэтому статический список ID не используется.
- Сейчас строки без `ttype` или с невалидным признаком пропускаются; когда таких все, инструмент сообщает только об отсутствии дискриминатора.

## Архитектурное решение

Проблема: нет достоверного признака для части строк, а оператор не знает, почему слот не вычислен. Варианты: (1) считать все строки рабочими — слишком легко превратить отпуск в свободные слоты; (2) вшить ID сидов — ненадёжно для тенантов; (3) явный `work_title` для строк с неизвестным признаком. Выбран (3): точное совпадение чувствительно к регистру, значение задаёт вызывающий; валидный признак справочника всегда имеет приоритет. Если неизвестных строк нет, `work_title` не меняет обычный расчёт. Если они есть, а выбранное название не найдено среди них, вернуть тот же информативный отказ. Без параметра любая неизвестная строка вызывает отказ: даже частично подтверждённое рабочее время может перекрываться неизвестным выходным. С параметром остальные неизвестные строки считаются занятыми интервалами по клинике, чтобы не выдавать слоты в перекрытии. Названия в отказе выводятся только из короткого списка типовых названий без ПД; прочие редактируются. Сам аргумент `work_title` также не возвращается в ответе или отказе. Полные названия доступны оператору через разрешённый `get_timesheets`.

Инварианты: обычный результат и геометрия слотов сохраняются; `is_working_hours=0` никогда не включается по одному title; неизвестная строка не становится рабочей молча; подсказка не содержит внешних адресов/секретов/произвольных названий; число слотов может быть завышено только в явно помеченном запасном режиме. Откат: убрать новый аргумент, предупреждения и совет повторить вызов с ним, восстановить строгую проверку, сохранив диагностическую часть отказа.

# Этап 250. Закрытия счёта по обеим сторонам

## Цель

Добавить `invoice_id` в `get_closing_of_invoices`, чтобы возвращать все closing records, где счёт находится на minus или plus стороне.

## Проверенные факты и декомпозиция

На devtr6 счёт встречается в обеих сторонах; один `minus_type_document` может быть пустым. При `invoice_id` выполнить два ограниченных GET по `minus_document_id` и `plus_document_id`, объединить rows, дедуплицировать по `id`, затем применить offset/limit. Без `invoice_id` сохранить старый один запрос.

## Архитектурное решение

Две явные запросные ветви отражают upstream модель и проще обобщённого поиска документов. Инвариант: пользовательский filter не может конфликтовать с `invoice_id`; совпадающая запись возвращается один раз, даже если сервер/данные дублируют её. Rollback: удалить параметр и helper. Architecture Critique: required (finance public API and multiple calls).

## Критерии готовности

Две стороны объединены, дубликаты удалены, пустой type не вызывает ошибку, пагинация применяется после merge.

# Этап 254.3. Фильтр деплоя обходится кириллицей в имени файла

## Оговорка о порядке

**PRD написан по ходу работы, 28.08.2026, после того как дефект нашёлся сам —
собственным коммитом.** Это не новая задача, а починка пункта, который этап 254
считал закрытым; PRD-review сторонней моделью до кода не проводился, ревью на
committed diff проведено (два валидных запуска).

## Цель

Документационный коммит не должен пересоздавать контейнер на проде — включая
коммит, который добавляет PRD с русским именем файла. То есть ровно та цель,
которую этап 254 объявил достигнутой.

## Контекст и проверенные факты

**Как нашлось.** Коммит `a1b2c3d` (ревизия статусов `in_progress`) содержал
только `Roadmap.md`, `AssumptionLog.md` и новый `PRD/этап-241-…md`. `Deploy Prod`
отработал целиком: rsync, remote deploy, пересоздание контейнера
(`Up 42 seconds` сразу после).

**Причина.** Гейт фильтровал вывод `git diff --name-only`. Эта команда
экранирует не-ASCII пути в октальные последовательности и заключает их в
кавычки: `"PRD/\321\215\321\202…md"`. Такая строка не начинается на `PRD/` и не
кончается на `.md`, поэтому условие «есть путь вне документации» истинно.

**Масштаб.** Все PRD репозитория названы по-русски, значит **любой коммит с
новым PRD** перезапускал прод. А поскольку Core Loop требует PRD на каждый этап,
это касалось значительной части коммитов.

**Почему тест этого не поймал.** `test_stage254_doc_only_deploy.py` проверял
наличие в workflow строки `git diff --name-only "${base_sha}" "${HEAD_SHA}"` и
самого регэкспа. Тест закреплял **форму реализации**, а не поведение, поэтому
оставался зелёным ровно на том коде, который содержал дефект.

**A/B на боевом CI.** Коммит `22a85f9` — те же два файла с латинскими именами,
без нового PRD — дал `deploy: skipped`, контейнер не тронут. Единственное
отличие от `a1b2c3d` — имя добавленного файла.

## Решение

1. Решение о скоупе вынесено в `scripts/deploy_scope_check.sh`: читает пути
   из stdin, разделённые NUL, печатает `true`/`false`.
2. Workflow отдаёт ему пути сырыми:
   `git -c core.quotepath=false diff --name-only -z`.
3. Пустой список по-прежнему означает `true`: отсутствие списка — не
   доказательство того, что коммит документационный.
4. Сопоставление ведётся `case`-шаблонами (`PRD/*`, `docs/*`, `*.md`), а не
   регэкспом по склеенному тексту — экранирование и переводы строк в именах
   перестают быть фактором.

**Что не делалось.** Не переносили в скрипт поиск базового коммита: он ходит в
GitHub API и в тестовом контейнере невоспроизводим. Разделение проведено ровно
по той границе, где начинается проверяемая логика.

## Проверки

- `tests/test_stage254_deploy_scope.py` — решение на списке путей: русский PRD,
  латинский документ, код, смесь, русское имя вне документационных путей, пустой
  диапазон, экранированная форма (она обязана читаться как «не документация»),
  и текстовый контракт workflow.
- Сторож на слив stdin: скрипт дочитывает список до конца, даже когда ответ уже
  известен. Показан красным на версии с ранним выходом — писатель получает
  `BrokenPipeError` на середине записи.
- `tests/test_stage254_doc_only_deploy.py` переписан с формы реализации на новый
  контракт, с пометкой, почему прежние утверждения благословляли дефект.

## Границы

Скрипт не знает, какие пути попадают в образ, — он знает список исключений.
Появится новая директория с документацией (или, наоборот, код в `docs/`) —
список надо править руками, автоматической связи с `Dockerfile` нет.

Финальная правка после исчерпания бюджета ревью (убийство процесса по таймауту
в стороже и уменьшение объёма входа) сделана без нового прогона и помечена
`deferred after 2 external-review iterations`.

# Этап 272. Состав группы считается из прав, а не пишется руками

## Проблема

Состав группы существует в реестре дважды. Реальный — инструменты, чьи
требуемые права входят в набор группы; именно его исполняет проверка вызова и,
с этапа 271, показывает каталог. Обещанный — руками написанный список
`MARKETED_PRESET_TOOLS`.

Списки разошлись, и сильно:

| Группа | Реально доступно | Обещано списком |
|---|---|---|
| Полный доступ | 119 | 119 |
| Только чтение | 92 | 88 |
| Регистратура | 71 | 24 |
| Врач | 55 | 17 |
| Финансы | 45 | 14 |
| Склад | 46 | 22 |
| Аналитик | 97 | 8 |

Тест проверяет только одну сторону — что обещанное входит в реальное. Избыток
не ловится вообще, поэтому расхождение росло годами незамеченным.

Цена не косметическая. Из обещанных списков строится текст отказа: «этот
инструмент доступен группам …». Сейчас у **92 инструментов из 119** этот
список неполон, и всегда в одну сторону — занижает. Первым в нём при этом
стоит «Полный доступ». То есть агент, упёршийся в отказ, читает «попросите
полный доступ» там, где хватило бы «Аналитика»: подсказка сама толкает
пользователей к самому широкому ключу.

## Решение

Убрать второй список. Состав группы считается из прав:

```
tools_for_preset(preset) = { инструмент | требуемые права ⊆ права группы }
```

`MARKETED_PRESET_TOOLS` удаляется, `get_presets_allowing_tool` строится на
вычислении. Тогда «обещано» и «доступно» — одно и то же по построению, и
расходиться нечему: тест на равенство двух списков не нужен, потому что списка
два больше нет.

Ровно то же правило уже используют проверка вызова (`_ensure_tool_scopes_allowed`)
и фильтр каталога (`visible_tools_for_scopes`, этап 271). Этап делает третье
место потребителем того же правила вместо собственной копии.

### Почему не «синхронизировать списки»

Синхронизация — это ещё один снимок, который снова протухнет: ровно так и
появилось сегодняшнее расхождение. Один источник дешевле любого сторожа за
двумя.

### Что при этом теряется

Возможность рекламировать **меньше**, чем группа может, — то есть курировать
список «для чего эта группа задумана». Сегодня этим никто не пользуется
осознанно: разница между 8 и 97 у «Аналитика» — это не курирование, а
забытый список. Понадобится курирование — оно вернётся как отдельное поле
описания группы, а не как второй перечень инструментов.

## Подзадачи

### 272.1 Вычисление состава

`tools_for_preset(preset)` в `tool_access_registry.py`.

Осторожно с инструментами без требуемых прав: буквальная формула
«требуемые права ⊆ права группы» пропускает **любой** инструмент с пустым
списком прав, а проверка вызова пропускает только поимённый список
`BASELINE_ALLOWED_TOOLS`. Инструмент, у которого права забыли проставить,
рекламировался бы всеми группами и запрещался на вызове — то самое
расхождение, которое этап убирает. Поэтому вычисление повторяет правило
проверки вызова буквально, а не приближённо, и добавляется инвариант:
множество инструментов с пустыми правами совпадает с `BASELINE_ALLOWED_TOOLS`.

`BASELINE_ALLOWED_TOOLS` при этом переезжает в реестр: это данные о правах,
а не о проверке, и реестр не может импортировать модуль проверки обратно.

### 272.2 Подсказка в отказе

`get_presets_allowing_tool` — на вычисление. Проверить, что для каждого
инструмента она называет **все** группы, которые его дают.

### 272.3 Удалить `MARKETED_PRESET_TOOLS`

Потребители — только реестр и четыре файла тестов. Сторожа, построенные на
этом списке, не удаляются, а переносятся на вычисление, иначе вместе со
списком пропадёт защита:

- `tests/test_stage268_…` — снятые инструменты удаления счетов не должны
  оказаться в составе ни одной группы;
- `tests/test_stage269_…` — запуск отчётов не должен предлагаться группам без
  права на отчёты;
- `tests/test_stage130_access_registry.py::test_report_ai_preset_advertises_full_report_ai_flow`
  — ожидает курированный список из восьми инструментов; переписывается на
  «весь поток Report AI доступен, и чтение, и запуск»;
- `tests/test_stage132_scope_enforcement.py` — закрепляет текст отказа со
  старым списком групп; ожидание обновляется под полный список.

### 272.4 Тесты

- для каждой группы состав из `tools_for_preset` совпадает с тем, что
  пропускает проверка вызова, — по всем инструментам;
- подсказка в отказе называет все дающие группы, для каждого инструмента;
- инструменты без требуемых прав входят в любую группу;
- сторож показать красным.

## Критерии приёмки

- в реестре один источник состава группы;
- текст отказа не занижает список групп ни для одного инструмента;
- прогон зелёный.

## Вне рамок

- порядок групп в тексте отказа и формулировка — этап 273;
- изменение самих наборов прав;
- показ состава в интерфейсе — этап 273.

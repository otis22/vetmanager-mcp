# Этап 396. Типы значений строк Report AI

## Проверенные факты и границы

`get_report_ai_job_data` возвращает `data.columns` и `data.rows`; контрактные и живые тесты подтверждают строковый список названий `columns`. OpenAPI v6 этот endpoint не описывает. Ответ проходит `redact_sensitive_output_fields`, затем для деперсонализованного ключа `sanitize_tool_result(report_mode=True)`, затем `canonical_tool`, который сохраняет динамические имена колонок по решению этапа 395. Превью создаётся другим инструментом и содержит вымышленные примеры. Объектная форма колонки `{name,type}` в реализации — защитная совместимость, а не подтверждённый контракт ВМ; неизвестная форма даёт безопасный fallback.

## Цель и критерии приёмки

Только в `get_report_ai_job_data.data.rows` пустая строка становится JSON `null`. Строки с числом в однозначно числовой колонке становятся JSON числом при сохранении десятичного представления и безопасного диапазона. Имена колонок и типы, если есть, определяют возможность конверсии; само значение тип колонки не определяет. Идентификаторы, коды, артикулы и телефоны остаются строками, включая `007`. При конфликтующей или отсутствующей метадате числа остаются строками. Уже замаскированные личные значения не восстанавливаются; это может давать разный тип одной ячейки для обычного и деперсонализованного ключа. `columns`, `total`, `preview_example_row`, прочие метаданные и все остальные инструменты сохраняют прежние типы. Значения строк и названия колонок из этапа 395 не переименовываются.

Матрица охватывает сумму `246800.0000000000`, дроби `1.25`/`0.1`, избыточную дробную точность, безопасную границу целого `2^53-1`, целое за ней, экспоненту `1e3 → 1000`, большой показатель `1e5000 → строка`, `-0`, невалидное число, пустую строку и `null`, коды с ведущим нулём, составные имена `clientId` и `КлиентИД`, конфликтующие типы одной колонки в обоих порядках и личные значения. Отдельный сторож подтверждает, что телефоноподобное `8.9161234567` в колонке «Сумма» маскируется существующим слоем. Живой тест требует непустой читаемый отчёт с числовым значением, выводит лишь HTTP-коды и агрегаты типов.

## Архитектурное решение

Нормализатор — чистая функция в отдельном модуле. MCP-обёртка вызывает её после редактирования и деперсонализации, до канонизации имён. Она копирует только `data.rows` конкретного инструмента; запрос, экспорт, метаданные и превью не меняются. Для строковых `columns` используется закрытый перечень числовых названий и отдельных слов в названии (`Общая сумма` распознаётся по слову «сумма»); идентификатороподобное название имеет приоритет запрета. Для объектных колонок учитывается явный числовой тип; явный текстовый тип и идентификатороподобное название запрещают конверсию. Повторное имя с любым нечисловым, отсутствующим или ошибочным типом запрещает конверсию всей колонки. При отсутствующих/неверных `columns` остаётся только замена `""` на `null` внутри rows.

`Decimal` разбирает числа. Целое выдаётся Python `int` только в диапазоне `±(2^53-1)`, чтобы типичный JSON-клиент IEEE-754 не округлил его. Для дроби используется `float`, только если `Decimal(str(float_value))` равен исходному значению. Прочие дроби остаются строками. Вход длиннее 128 символов, коэффициент длиннее 100 цифр или абсолютный десятичный показатель степени больше 100 остаются строками до расширения в `int`. `-0` сохраняет строку и знак. Нормализация выполняется после очистки, поэтому замаскированная длинная сумма остаётся строкой; приватность важнее числового типа. Общие regex и регистр деперсонализации не меняются.

Альтернативы: `float` для всех строк теряет точность и меняет коды; `Decimal` напрямую сериализуется FastMCP строкой; определение числового столбца по значению превращает `007` в `7`. Линейная стоимость по числу ячеек при лимите upstream 10 000 строк. Публичный контракт меняется на существующем инструменте. Перед выпуском обязательны матрица, живой отчёт, сильные verdict и полный suite. Описание инструмента сообщает о типах. После публикации исправление должно сохранять уже гарантированные числовые имена и сужать классификатор для спорных колонок; при приватностном дефекте маскирование имеет приоритет и может вернуть строку. Операционный аварийный возврат: владелец принимает несовместимость, предупреждает потребителей, команда откатывает выпускной commit и повторяет полный suite и CI перед развертыванием. До публичного выпуска этот же git revert возможен без оповещения. Молчаливый возврат строк после публикации запрещён.

Architecture Critique совмещён с сильным PRD-review ввиду публичного MCP-контракта и границы приватности.

## Декомпозиция

1. Контрактные сторожа и красная матрица (≤ 2 ч): значения, метаданные, приватность, обычный/деперсонализованный ключ.
2. Нормализатор и подключение в MCP-обёртке (≤ 150 строк).
3. Живой запуск и чтение отчёта на заранее выбранном `.env`-контуре, только безопасные агрегаты (≤ 2 ч).
4. Spark → Astra + Sol, аудит, фокусные тесты, один выпускной mock+real suite, журнал, commit/push/CI (отдельный ход при нехватке времени).

## Простота и итоги review

Один модуль и одна точка подключения; новые слои в деперсонализации не вводятся. Spark указал на fallback метаданных, числовые края, русский `ИД` и откат — принято. Astra нашла опасное исключение для суммы и большой показатель степени — оба исправлены; замечание о прежней ошибке теста также исправлено. Sol нашёл противоречия прежних добавочных уточнений, диапазон IEEE-754, `clientId`, повторные метаданные, слабый живой критерий и совместимость — всё принято. Вторая сильная пара нашла префикс `ID`, ошибочный тип повторной метадаты и необходимость доказать реальное преобразование на стенде; все три замечания закрыты. Живой свидетель: из 12 строк сырого ответа 12 числовых строк стали числами, другие 12 строк остались строками; в журнал выводятся только типы и HTTP-коды. Claude Opus не запускался по прямому указанию владельца.

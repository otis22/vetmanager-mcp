# Этап 449. Синоним `id` для `*_by_id`

## Цель

Любой инструмент `*_by_id` принимает `id` как синоним своего основного параметра, сохраняя существующую схему с именованным параметром. Конфликт двух разных значений даёт понятную ошибку до обращения к Vetmanager.

## Проверенные факты

Sentry PYTHON-2D: клиент `codex-mcp-client/0.162.1` вызвал `get_admission_by_id({"id": N})`; FastMCP отклонил вызов до тела инструмента. В проекте `IdentifierAliasMiddleware` уже нормализует вход до валидации, а `canonical_tool` публикует сигнатуру. `tools/list` обязан оставаться источником схемы. Справочник API подтверждает идентификаторы сущностей, но это изменение только MCP-входа, REST payload не меняется.

## Архитектурное решение

При регистрации `*_by_id` извлекать единственный обязательный параметр ID из публичной сигнатуры и регистрировать соответствие для middleware. Middleware переводит `id` в именованный параметр перед FastMCP validation, проверяя конфликт. Не добавлять `id` в `inputSchema`: основное имя остаётся видимым. Если будущий `*_by_id` не имеет ровно одного ID, регистрация должна выявить это как ошибку, а не угадывать. Architecture Critique требуется: меняется публичный MCP-контракт.

Основной ID — единственный обязательный параметр публичной сигнатуры с суффиксом `_id`; если он уже называется `id`, перевод не нужен. Нормализация `id` идёт после существующих `patient_id`/`owner_id`/`user_id`, чтобы конфликт проверялся с каноническим именем. Значения сравниваются без приведения типов, как в текущей `normalize_arguments`: `"5"` и `5` конфликтуют, одинаковые тип и значение допускаются.

Проверка кода выявила существующее исключение: `get_medical_card_by_id` уже публикует `card_id` и `id`, требует ровно один аргумент и сам валидирует их. Его контракт сохраняется; новая общая нормализация применяется к остальным `*_by_id` без опубликованного `id`.

## Подзадачи и приёмка

1. Красный параметризованный тест по всему каталогу `*_by_id`: `id` работает, оба одинаковых работают для новых алиасов, разные значения отклоняются до I/O, схема показывает старое имя. Отрицательный тест: `id` вне `*_by_id` не переписывается; существующий инструмент медкарты сохраняет свой контракт.
2. Изменить общую границу аргументов и выполнить живой вызов на разрешённом стенде.
3. Полный mock и real suite, ревью committed diff, выпуск ветки.

## Простота

Один регистрационный список, построенный из фактических сигнатур, и одна ветка middleware проще ручной правки тридцати инструментов и не рассинхронизируется при добавлении следующего `*_by_id`.

# Этап 417. Деперсонализация Report AI в подсказках агенту

## Цель и проверенные факты

Агент снизил оценку готового отчёта из-за отсутствия ФИО, указав «режим без ПД». По решению владельца ожидаемое поведение Report AI шире исходного случая: отчёт предпочитает деперсонализированный вывод и может заменить ФИО и телефоны плейсхолдерами даже при токене с ПД. Этапы 275–278 закрепили обязательную очистку отчётных данных в MCP для токена без ПД; для токена с ПД такой обязательной очистки нет. Наличие доступа к ПД не гарантирует их выдачу в конкретном отчёте. Текст объясняет предпочтение конструктора, не обещает принудительную очистку всех ответов.

`tool_descriptions.py` публикует описания `create_report_ai_job`, `get_report_ai_job`, `get_report_ai_job_data` и `rate_report_ai_job` через `tools/list`. `prompts.py:get_report_ai_prompt_helper_text` читает `artifacts/report-ai-prompt-helper-short-mcp-2026-06-15.md`; одно тело возвращают MCP prompt `report_ai_prompt_helper` и tool `get_report_ai_prompt_helper`. Шкала этапов 400/408/409 уже записана в описании `rate_report_ai_job` и справке: 1 — не построился, 2+ — построился, 5–6 — решил частично, 10 — решил полностью; финальный шаг `rate_report_ai_job(job_id, score, intent_text)` остаётся обязательным при наличии job ID. Главный PRD требует полезного `tools/list`; технические требования называют централизованные описания и MCP prompts. Нового REST-вызова нет, OpenAPI не затрагивается.

## Архитектурное решение

**Проблема:** агент интерпретирует плейсхолдер как дефект качества отчёта. **Варианты:** менять очистку/права (противоречит принятой модели), менять шкалу (ломает канон оценки), уточнить тексты в существующих точках чтения (выбрано). Уточнение будет рядом с шагами создания, просмотра статуса, чтения строк и финальной оценки, а также в коротком маршруте справки перед оценкой. Оно объясняет ожидаемую замену и велит оценивать решение задачи по доступным данным, не снижая балл только из-за отсутствия ПД, если задача решена без них. Если нужный критерий, фильтр, агрегат или необходимые для контактного действия ФИО/телефон действительно не получены, оценка всё ещё может быть низкой; агент сообщает человеку об ограничении. Плейсхолдер не объявляется реальным ФИО/телефоном или способом восстановления ПД.

Инварианты: неизменны сигнатуры, права, REST, очистка, шкала 1–10, обязательный `intent_text`, порядок create → poll → data → rate, возможность честно снижать оценку за неполное решение задачи. Одинаковое пояснение в трёх англоязычных описаниях хранится одной константой; русские тексты оценки и справки остаются самостоятельными в своих точках публикации. Откат — вернуть добавленные фразы и соответствующие сторожа вместе; если upstream изменит поведение, сначала подтвердить новый внешний контракт и обновить тексты отдельной задачей. Architecture Critique: not required — изменение ограничено объяснением уже принятого публичного контракта без смены архитектуры, API или ownership.

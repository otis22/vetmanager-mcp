# Этап 437. Оценка Report AI при сохранении отчёта

## Цель

На 23.10.2026 оценено 14 из 48 сохранённых отчётов (29 %), reminders в БД — 21; 9 свежих отчётов за сутки без оценки. Отдельное напоминание приходит позже сохранения. Существующий `rate_report_ai_job(job_id, score, intent_text, comment)` принимает 1–10, где 1 означает, что отчёт не построился, 2 и выше — построился, 10 — задача решена полностью. `comment` необязателен. `save_report_ai_job_as_report` возвращает JSON с `data.report_id`, `data.is_idempotent` (если прислал upstream) и `data.next_action` для чтения строк. До оценки полезности агенту нужно прочитать реальные строки через `get_report_ai_job_data`. Главный PRD требует понятный агенту путь к результату, технические требования — совместимость MCP и деперсонализацию. Контракт REST сохранения определяется ответом `/rest/api/report-ai-job/{id}/save`; новый текст добавляется нашим MCP слоем, upstream не меняется.

## Архитектурное решение

**Проблема:** агент видит успешное сохранение, но не видит шкалу и непосредственный призыв оценить итог; следующий reminder приходит позже.

**Варианты:** заменить `next_action` оценкой — агент потеряет указание прочитать строки; расширить глобальный `REPORT_AI_RATING_GUIDANCE` — изменит другие ответы и не акцентирует момент сохранения; добавить отдельное текстовое поле в конец `data` успешного сохранения — локально, совместимо и без дополнительного запроса. Выбран третий вариант. `data.mcp_rating_prompt` содержит статический текст: **сейчас** открыть реальные строки через `get_report_ai_job_data`, выполнить предписанный этим ответом полный просмотр (при `limited=true` — экспорт), затем одним вызовом `rate_report_ai_job(job_id, score, intent_text, comment?)` оценить результат; указаны границы шкалы и необязательность комментария. Если данные говорят, что оценка уже есть, не заменять её автоматически. `intent_text` — исходный запрос создания, его значение в ответ не копируется; если он недоступен, не выдумывать его ради рейтинга. В поле нет данных клиники или персональных данных.

**Инварианты:** существующие `success`, `message`, `data.report_id`, `data.is_idempotent` и `data.next_action` не меняются; prompt добавляется только при успешном сохранении с валидным `report_id`, включая идемпотентный ответ; error/unknown outcome не получают призыва; reminders продолжают работать. Деперсонализация получает только статический текст. Не выполняем рейтинговый вызов автоматически: полезность определяет агент после чтения строк. Откат — удалить одно добавление поля, миграция не нужна.

**Риски:** оценка до полного чтения строк может исказить метрику. Поэтому порядок прямо указан: открыть данные сейчас, выполнить дальнейшие указания данных и после полного просмотра оценить. `rate_report_ai_job` перезаписывает оценку для того же задания, дублирующей строки нет; `get_report_ai_job_data` уже сообщает, когда рейтинг завершён, и reminder проверяет `has_unrated_job`. Доля оценённых считается по уникальным job ID; причинность изменения без контролируемого эксперимента не утверждается. Если отчёт не построился, прежний путь оценки с score 1 сохраняется. Изменение публичного MCP ответа требует Architecture Critique; совместить с PRD review, проверив scope, альтернативы, приватность, совместимость, критерии и откат.

## Декомпозиция и приёмка

1. **437.1 (≤150 строк теста):** текстовый сторож через MCP на успешное и идемпотентное сохранение. До реализации показать red. Проверить призыв «сейчас», имя инструмента, 1–10, границы 1/10, один вызов, необязательный комментарий, порядок чтения строк и указания полного экспорта/готовой оценки, неизменность существующих полей; error/unknown без prompt. Отдельной мутацией удалить фразу и убедиться, что сторож краснеет. Существующие тесты `get_report_ai_job_data` и reminder подтверждают ветки `limited=true`/уже оценено; новое поле не меняет эти ветки.
2. **437.2 (≤150 строк кода):** добавить статический блок в конце `data` успешного сохранения; фокусные тесты; живой вызов на devtr6 с обезличенным сохранением и кодом/телом ответа; аудит, committed diff review, mock+real suite один раз по финальному SHA, push и зелёный CI ветки. Reminders остаются. Пострелизный замер доли оценённых за 7 дней против 29 % — задача супервизора после релиза.

## Простота

Один статический текст и одно присваивание в уже существующем успешном пути, без новых API, хранилищ и фоновых заданий.

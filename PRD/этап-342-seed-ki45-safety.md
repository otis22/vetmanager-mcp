# Этап 342. Безопасный seed известных проблем

## Проблема и факты

После этапа 340 production `--dry-run` сообщил `created=1 updated=1 unchanged=10`.
Обновляемая KI-45 имеет правила и playbook новее seed. Этапы 332–335 применяли
`artifacts/known-issues/stage-332/ki45-match-rules.json` и `ki45-playbook.json`;
`scripts/apply_stage332_known_issues_prod.sh` читает эти файлы. Полного прод-снимка
в этом этапе нет; его не реконструируем по обрезкам. Супервизор проверит
`updated=0` после деплоя. KI-63 и остальные записи по существу не меняем.

## Архитектурное решение

Проблема — две независимые копии конфигурации KI-45 и опасное поведение `--apply`.
Контекст: seed сравнивает управляемые поля по существующему маркеру, счетчики
оставляет БД; миграционный скрипт уже читает JSON-файлы. Нет новых REST/API/MCP
контрактов, обращений к production и миграций БД. Для этой задачи OpenAPI не
задаёт контракт локального seed. Главный PRD и технические требования не задают
формат синхронизации известных проблем; опираемся на существующий код и артефакт.

Варианты: дублировать JSON в Python и проверять равенство тестом (остаётся две
точки правки); перенести миграцию на Python-модуль (потребовало бы менять старый
production-скрипт); читать существующие JSON-файлы в seed. Выбран последний:
единственный источник правил и playbook для обоих путей, старый скрипт не меняем.

Сравнение JSON-полей структурное: скрипт 332 сохраняет JSON с пробелами, seed
сейчас сериализует компактно. Если содержимое равно, seed считает поле
неизменённым и не переписывает его. Тест использует сериализацию triage.

`--dry-run` показывает имя KI и названия отличающихся полей. `--apply` создаёт
отсутствующие записи как раньше, но при любом `updated>0` завершает транзакцию
без commit, сообщает поля и требует `--allow-update <slug:field,field>` для каждой
обновляемой KI. Перечень полей обязан в точности совпадать с текущим diff;
при нескольких расхождениях неперечисленная KI отменяет всю
транзакцию с ненулевым exit code. Оператор сначала сверяет dry-run; `--apply`
повторно читает текущее состояние и показывает актуальные поля до записи.
Строки KI блокируются для записи на время проверки и commit. Печать значений
запрещена: конфигурация и playbook могут содержать чувствительный текст.
README объясняет новый порядок.

Инварианты: KI-45 из seed структурно равна файлам 332, а скрипт 332 использует
те же файлы; без флага существующие KI не перезаписываются; create-only и
идемпотентный повтор работают; counters не затрагиваются. Тесты ловят
расхождение и демонстрируют красный результат на исходном коде. Rollback:
откатить изменение seed до применения; после явного применения восстановление
конкретной KI — отдельная операторская операция из полной резервной копии БД
до разрешённой перезаписи. `show-known-issue-config` недостаточен: не содержит
всех seed-полей. Seed не обещает автоматический rollback и не хранит снимки;
README требует полную резервную копию перед использованием флага.

Architecture Critique обязателен из-за production-поведения seed; он совмещён
с полным PRD-review (архитектура, scope, тесты, rollout и rollback).

## Подзадачи и критерии приёмки

1. 342.1 (≤ 2 ч): guard сравнивает seed KI-45 с обоими JSON и проверяет ссылки
   в скрипте 332; после изменения guard зелёный. Тест проверяет наличие файлов
   в production image по Dockerfile/COPY и исключениям сборки. AST-сторож имён
   инструментов также читает общие JSON-файлы и отказывает на неизвестных
   именах, отсутствующих файлах и неразбираемых правилах.
2. 342.2 (≤ 2 ч): тесты red/green для отказа `--apply` при расхождении,
   перечня полей без значений, явного `--allow-update`, смешанного drift,
   атомарности и
   сохранения create-only/идемпотентности.
3. 342.3 (≤ 2 ч): README с обязательным просмотром `--dry-run`, порядком
   явной перезаписи; фокусные, audit, review, один полный mock и real suite.

## Выпуск

Production не трогаем. После Deploy Prod супервизор запускает read-only
`python scripts/seed_known_issues.py --dry-run` внутри production-контейнера
и сверяет KI-45: `updated=0`, в существующих `unchanged`. Если остался drift,
остановить применение seed и снять полный read-only конфиг KI-45 для разбора;
обрезанный снимок постановки не доказывает совпадение остальных управляемых
полей. Автоматических вызовов общего seed в Dockerfile, compose и workflow
нет; тесты вызывают функцию напрямую. README — единственный найденный
операторский `--apply` call-site.

# Этап 279. Роадмап теряет пункты молча

## Контекст

`Roadmap.md` объявлен в `AGENTS.md` единственным источником очереди работ.
На 02.09.2026 это 5391 строка и 287 заголовков этапов. Читать его глазами
целиком уже нельзя, а никакой машинной проверки структуры у него нет: гейты
`review_workflow_check.sh` и `check_stage_completion.sh` проверяют связку
«этап → PRD → AssumptionLog», но не сам файл очереди.

## Проверенные факты

Разбор 02.09.2026 собственным скриптом по текущему `Roadmap.md`:

| Что | Сколько | Пример |
|---|---|---|
| заголовков этапов | 287 | — |
| статусов `done` | 271 | — |
| статусов `todo` | 10 | этап 223 |
| статусов `stop` | 4 | этап 149 |
| статусов `in_progress` | 2 | этапы 235 и 237 |
| незакрытых пунктов внутри закрытых этапов | 2 | 249.3, 266.4 |
| пунктов с чужим номером | 1 | 97.7 под заголовком этапа 104 |
| открытых этапов без единого пункта | 1 | 231 |

Отдельно проверено: поиск по строке `in-progress` (через дефис) не находит
ничего, потому что в файле используется `in_progress`. То есть два открытых
этапа из одиннадцати выпадают из очереди при поиске, написанном по памяти.

## Цель

Структурные ошибки роадмапа должны падать в CI, а не обнаруживаться разбором
раз в полгода. Плюс разово убрать те четыре, что уже накопились.

## Scope

- **279.1** `scripts/check_roadmap_structure.py` — пять проверок:
  1. заголовок этапа несёт статус из словаря `todo | in_progress | done | stop`;
  2. каждый пункт несёт статус из того же словаря;
  3. номер пункта `N.M` совпадает с номером своего этапа `N`;
  4. этап `done` или `stop` не содержит пунктов `todo` / `in_progress`;
  5. этап `todo` или `in_progress` имеет хотя бы один пункт.
- **279.2** Тест `tests/test_stage279_roadmap_structure.py` гоняет гейт по
  настоящему `Roadmap.md` и по образцам-нарушителям.
- **279.3** Вынести остатки: 249.3 → 246.6, 266.4 → этап 280, 97.7 → под этап 97.
- **279.4** Этап 231 → `stop` с причиной.
- **279.5** Снять расхождение 249.3 и 246.3.

## Acceptance

- Гейт зелёный на `Roadmap.md` после правок и красный на каждом из пяти
  образцов-нарушителей — каждая проверка показана падающей отдельно.
- Проверки 3 и 4 показаны красными на настоящем файле до правок: гейт обязан
  был поймать 97.7, 249.3 и 266.4.
- Полный прогон набора зелёный.

## Out of scope

- Разбиение `Roadmap.md` на файлы по годам или направлениям. Проблема здесь —
  не размер, а отсутствие проверки; резать файл до появления гейта значит
  разнести те же ошибки по нескольким местам.
- Проверка содержания пункта (осмысленность формулировки, наличие источника).
  Гейт судит структуру, а не качество текста.
- Автоматическая правка файла. Гейт сообщает и падает; правит человек или агент.

## Оценка простоты

Один файл разбора на ~150 строк без зависимостей и один тест. Альтернатива —
дописать проверки в существующий `review_workflow_check.sh` на bash+awk —
отклонена: разбор многострочных пунктов с продолжением на awk выйдет длиннее
и непроверяемее самого правила.

## Риски

- **Ложное срабатывание на историческом тексте.** 271 закрытый этап писался без
  этих правил. Снимается тем, что гейт прогоняется по настоящему файлу до
  коммита и все найденные нарушения либо чинятся, либо правило сужается — но
  не заводится список исключений: исключения гасят гейт молча.
- **Статус в тексте пункта.** Пункт может упоминать `done` внутри фразы. Статусом
  считается последний токен словаря в строке пункта; на настоящем файле это
  проверено полным прогоном.

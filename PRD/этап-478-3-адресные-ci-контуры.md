# PRD 478.3 — адресные CI-контуры (PR 478B-2)

## Цель и границы

Сократить PR-проверки для изолированных изменений без потери обязательных
test nodes, coverage, манифестов и строгой политики warning/skip. Ветка
`dev/roadmap-478b-2`, base `5eb7082f01ed00b7d64dff8e27f7201e5094d390`.
Nightly, измерение эффекта (478B-3), продуктовый runtime, публичные MCP-контракты
и production данные не входят. PR, merge и deploy выполняет куратор.

## Проверенные исходные факты

- `test_contours.py`: fast — default без `offline_integration`; default — все
  offline nodes, кроме `real_api`, `real_browser`, `postgres`.
- `scripts/offline_gate_manifest.py`: versioned per-file count+SHA для default и
  postgres; JUnit gate требует точный набор, zero skip/failure/error, fingerprint.
- `.github/workflows/test.yml`: fast, inventory-preflight, default, postgres,
  validated-tree; main reuse основан на точном tree и успешном PR run.
- Основной PRD и technical requirements сохраняют Docker как штатный test
  runtime и bearer-only MCP; API-поведение не меняется.

## Архитектурное решение

Версионировать однозначные правила выбора по путям в
`scripts/test_impact_map.json`. Малый CLI получает diff base..HEAD в PR и
выдаёт план. Разрешённый изолированный путь выбирает owning nodes по
versioned inventory; общие файлы, неизвестный статус/путь, неоднозначность,
ошибка карты или пустой выбор — полный набор. Правила карты/выбора, CI
workflow, runners, manifests, inventories и test collection — всегда full,
даже если ошибочно перечислены как isolated. Новые nodes требуют обновления
versioned inventory в том же PR; preflight отклоняет drift до suite.
Узкое исключение для существующего owning test: его `M`-изменение допускается
в том же PR с явно картированным инструментом; добавление тестового файла,
чужой тест и правка inventory выбирают full. Если collection в таком PR
дрейфует, preflight блокирует запуск до обновления inventory, а его правка
делает план full. CI всегда делает ранний inventory preflight. Узкий PR
запускает fast и выбранные owning/non-fast
nodes; полный PR запускает fast и оставшуюся часть default плюс PostgreSQL.
Карта и selector входят в fingerprint default/PostgreSQL как decision inputs.
CI fast разбивает файлы fast на десять непересекающихся shard в отдельных
CI runners, чтобы ресурсные пики не мешали тестам. Aggregate job проверяет
точный union их JUnit и объединяет coverage до передачи в default. Цель —
сохранить лимит каждого shard ≤180 секунд при branch coverage; обычный локальный
fast остаётся последовательным.
По диагностическому профилю три scanner nodes в общем shard занимали
31,54/31,07/30,74 с, а одна подсказка 23,38 с; их owning files исполняются
в двух отдельных чистых процессах. Остальные восемь shard сохраняют прежний
состав за вычетом этих файлов.
Default runner исполняет только дополнение по точному списку node IDs из текущего collection, тоже с
JUnit и отдельным coverage data. Aggregate gate принимает оба JUnit, сверяет
каждый с планом, их непересечение и объединение с точным ожидаемым набором
плана, zero skips и один исходный/конечный fingerprint. Пустой remainder
явно указан в плане: pytest для него не запускается, фиктивный JUnit или
coverage не создаётся. Full-план требует
равенства всему default inventory; isolated-план требует fast плюс все owning
nodes выбранных файлов. Исключённые nodes перечислены в evidence с основанием
из карты. Затем `coverage combine` с явными data files реально запущенных
partitions создаёт единый XML; отсутствие требуемого файла блокирует gate.
В проекте нет числового coverage threshold: isolated публикует фактический XML,
full сохраняет coverage всего default и сравнивается с монолитным baseline
при приёмке. Для локального штатного `docker compose ... test` сохраняется
полный default. PostgreSQL при любом затронутом PG-входе запускается целиком:
восемь обязательных файлов, inventory и manifest не дробятся. Marker validated-tree
публикуется только для full-плана; после isolated PR main выполняет полный
suite, так как reuse marker отсутствует. `workflow_dispatch` всегда full.

Простой вариант «всегда полный default» не удовлетворяет уменьшению длительного
suite при isolated tool. Выбор только по имени тестового файла без проверки
union/manifest рискует потерей node при изменении collection или marker.

## Матрица решения

| Изменение | PR | main | nightly |
| --- | --- | --- | --- |
| docs-only | действующий 478A путь | действующий reuse | 478B-3 |
| isolated tool + owning tests | fast + owning + явно указанная в карте PostgreSQL-зависимость | полный (узкий PR не публикует marker) | 478B-3 |
| shared runtime/config/fixtures | fast + полный remainder/default + PostgreSQL | полный или exact-tree reuse по действующему правилу | 478B-3 |
| unknown/ambiguous path или карта | полный offline + PostgreSQL | полный | 478B-3 |

## Декомпозиция

1. Контракт карты, дифф-парсер, план и guards fail-closed (≤150 строк за шаг).
2. Remainder/owning runner, JUnit union и coverage aggregate с guards (≤150 строк за шаг).
3. CI wiring и границы PR/main/reuse; brief-роль `test-contours` в
   существующем `/super-review`, обязательная при полном super-review и
   изменении CI/test-контуров. Отсутствие роли — ошибка coverage ролей,
   не одобрение. Владелец — reviewer orchestration (≤150 строк за шаг).
4. Inventory preflight, focused red/green, fast, ревью, финальные контуры,
   evidence и handoff (≤2 часа на подзадачу).

## Acceptance и обязательные guards

- Изолированный инструмент не запускает незатронутый долгий suite; owning
  выбирается детерминированно из versioned inventory.
- Shared/unknown/ambiguous/malformed map/status/diff → полный набор.
- Каждый выбранный node ровно один раз в fast ∪ remainder; пустой remainder
  допускается без фиктивных evidence. Full-план равен
  всему default inventory, isolated — fast + явно владеющие nodes. JUnit и
  план совпадают, no skipped/failed/error, fingerprint совпадает; coverage
  объединена в один XML без придуманного порога. Для PostgreSQL карта явно
  указывает необходимость полного PG-контура; неоднозначность и отсутствие
  признака при затронутом PG-файле включают полный набор. PostgreSQL
  inventory/manifest остаются обязательными при выборе PostgreSQL.
- Мутации удаления/дублирования node, skip, stale inventory/fingerprint и
  переименования пути краснят guard. Никаких suppression/xfail.
- Роль `test-contours` проверяет карту, выбор, nodes, инвалидацию и границы
  PR/main/nightly; агрегатор учитывает роль.
- Не затрагиваются real/browser без изменения их входов. Обязательный
  локальный default и применимый PostgreSQL проходят после freeze.

## Rollout и rollback

Rollout только в PR CI. При сомнении план возвращает full; ошибки aggregate
блокируют validated-tree. Rollback — вернуть CI к прежнему полному default и
PostgreSQL, сохранив versioned inventory и guards. Старые markers не
переиспользуются благодаря проверке exact workflow blob: main сначала
выполнит полный suite. Продуктовый deploy не нужен.

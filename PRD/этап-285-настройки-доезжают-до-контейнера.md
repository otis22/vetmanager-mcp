# Этап 285. Настройка, которую читает рантайм, доезжает до контейнера

## Цель

Убрать третье состояние настройки. Их должно быть два: либо оператор может
задать значение и оно действует, либо значение зашито в коде и из окружения не
читается. Состояние «код читает, задать нельзя» — источник тихих дефектов:
приложение видит пустую строку, ведёт себя по умолчанию, и ничто не падает.

## Проблема

Найдено при разборе дефекта 284.7: `SUPPORT_EMAIL` записали в `.env` на проде,
деплой прошёл, страница уехала — почта в кабинете не появилась. Сервис `mcp`
перечисляет переменные окружения поимённо, `.env` — только источник подстановки.

Первый счёт показал двенадцать таких настроек. Он был занижен вдвое: считалась
единственная форма чтения — `os.environ.get("ИМЯ")` в корне, `tools/` и
`vm_transport/`. Мимо проходили пакет `auth/`, обёртки `env_int` / `env_float`,
`_is_truthy_env` и `get_rate_limit_config("ПРЕФИКС")`, который собирает имя из
префикса — литерала `WEB_LOGIN_RATE_LIMIT_ATTEMPTS` в коде нет вовсе.

Реально: рантайм читает 51 имя, объявлено 21, не доезжало 30.

## Что меняется

1. Тридцать переменных объявлены в сервисе `mcp`. Пустое значение означает
   «поведение по умолчанию из кода»; строка нужна ровно для того, чтобы
   переменная существовала внутри контейнера.
2. Сторож проверяет весь рантайм, а не пересечение с `.env.example`. Знает все
   формы чтения, включая имя, собранное из префикса.
3. У сторожа есть тест на собственные зубы: сузить извлекатель — простейший
   способ сделать его зелёным, поэтому по представителю каждой непрямой формы
   проверяется явно.
4. Признан второй канал доставки — сборка образа (`ARG` → `ENV` в
   `Dockerfile`), но узко и с проверкой: имя засчитывается, только если
   `Dockerfile` действительно его закрепляет.
5. `.env.example` описывает настройки безопасности с последствиями, а тонкую
   настройку перечисляет именами без дублирования значений по умолчанию.

## Безопасность (285.2)

На боевом контуре до этого этапа:

| Настройка | Что действовало | Последствие |
|---|---|---|
| `WEB_ENABLE_HSTS` | выключено, nginx заголовок тоже не ставил | первый заход по http ничем не защищён |
| `WEB_TRUSTED_PROXY_IPS` | пусто | `X-Forwarded-For` от nginx не принимался |
| `FORWARDED_ALLOW_IPS` | пусто | то же на уровне uvicorn |
| `WEB_SESSION_SAMESITE` | `strict` по умолчанию | приемлемо |

Пустой список доверенных прокси означал, что клиентом считался шлюз докер-сети
`172.18.0.1`: привязка токена к IP привязывала всех к одному адресу, лимиты
входа и регистрации считались в общее ведро, а в аудит писался один и тот же
адрес.

## Пустое значение — не то же, что отсутствие (285.5)

Найдено внешним ревью диффа. Объявление `NAME: ${NAME:-}` кладёт в контейнер
пустую строку; читатель вида `int(os.environ.get("NAME", "10"))` получает `""`,
дефолт не применяется, процесс падает. Первая версия исправления снесла бы
боевой контур при выкате.

Правила два, потому что одного мало:

1. **Форма объявления.** Сквозная передача голым именем в списке: значение
   попадает в контейнер, только если задано. Проверено на живом compose —
   `- NAME` даёт отсутствие переменной, `NAME=${NAME:-}` даёт пустую строку.
2. **Терпимость читателя.** Числовые настройки читаются через `env_int` /
   `env_float`, которые на пустом значении возвращают дефолт. Оператор может
   написать `DB_POOL_SIZE=` руками, и падать из-за этого нельзя.

## Границы

Поведение приложения не меняется: правки в `storage.py`, `web_auth.py`,
`web_security.py`, `host_resolver.py` и `vm_transport/pool.py` заменяют сырое
приведение типа на терпимый хелпер с тем же дефолтом. Остальное — объявление
сервиса, пример конфигурации и значения на боевом контуре.

## Проверка

`tests/test_stage285_runtime_env_reaches_container.py`:

- каждое читаемое рантаймом имя доставляется сервисом или образом;
- извлекатель видит все формы чтения, включая хелперы и чтение по константе;
- канал образа остаётся списком из одного имени;
- настройки безопасности объявлены поимённо.

`tests/test_stage285_empty_value_keeps_defaults.py`:

- ни одно объявление не превращает незаданную настройку в пустую строку;
- каждая числовая настройка переживает пустое значение через тот слой,
  который её действительно читает.

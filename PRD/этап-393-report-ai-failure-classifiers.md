# Этап 393. Классификаторы отказов Report AI, волна 2

## Цель и контракт

Источник — triage 15.10.2026, KI 58/59/60. У PREVIEW_FAILED поле `error_message_safe` может содержать сырой SQLSTATE и `good_tag`: ВМ ограничивает текст 500 символами, а не очищает SQL. MCP классифицирует это до удаления текста. Для HTTP 500 чтения строк сохранённого job ВМ возвращает `INTERNAL_ERROR` и «Внутренняя ошибка», без SQL. Конфигурацию production `known_issues` этап не меняет.

## Приёмка

- Только failed/PREVIEW_FAILED с токеном `good_tag` (границы идентификатора, без совпадения с `my_good_tag_extra`) и одновременным `SQLSTATE` + явным текстом `syntax error`/`SQL syntax`/`синтаксическая ошибка` без учёта регистра получает отдельный `mcp_workaround`: известный дефект ВМ для состава комбинаций, `safe_to_retry=false`, вместо повторного отчёта — прямые инструменты `get_good_combination` и `calculate_good_combination_price` с явным `clinic_id` нужной клиники у каждого. Эта ветка проверяется до good.id и provider классификаторов: при пересечении маркеров безопасное `safe_to_retry=false` побеждает. Сырой SQL не выходит. Отрицательные случаи: один маркер, иной error_code/status, включение маркера в длинный идентификатор.
- `get_report_ai_job_data` при HTTP 500/`INTERNAL_ERROR` получает безопасную адресную подсказку: чтение строк можно повторить позже или проверить превью; успешный save не откатывается и данные не считаются потерянными. `safe_to_retry=true`. Исходные HTTP/code сохраняются, а `feedback_safe_excerpt` фиксирован и не содержит произвольный ответ ВМ. Исторический fingerprint меняется; match rules KI 60 по tool и признакам `unknown`/`internal`/`500` остаются достижимы и проверяются тестом. Прочие ошибки не переименовываются.
- Описание `create_report_ai_job` и prompt-helper говорят: колонка «Текущий остаток на складе» суммирует остаток по всем складам базы и игнорирует фильтр клиники; для остатка клиники применять `get_good_stock_balance` с явно указанным `clinic_id` нужной клиники (у инструмента есть default 1, который нельзя принимать молча).
- Красные сторожа проверяют сырой SQLSTATE + `good_tag`, отрицательные совпадения и HTTP 500/`INTERNAL_ERROR` на пути инструмента. Живая проверка на заранее выбранном контуре; если точный отказ нельзя безопасно воспроизвести, показать живой вызов затронутого инструмента с HTTP-кодом и безопасным телом.

## Декомпозиция

1. Контракт, PRD, Architecture Critique и PRD-review; уточнить поверхностные инварианты (≤ 2 ч).
2. Сторожа и показ красного на исходном коде (≤ 150 строк тестов).
3. Классификаторы и тексты инструментов/помощника, фокусные тесты и живой вызов (≤ 150 строк кода).
4. Аудит, committed diff review, один полный mock+real suite по финальному коду, выпуск и CI (≤ 2 ч).

## Архитектурное решение

Проблема: конфигурация KI не видит SQL, который MCP удаляет из job, а общий отказ HTTP 500 не сообщает безопасного действия. Классификатор PREVIEW_FAILED ставится в `tools/report_ai.py` рядом с существующим good.id до очистки. `_call_vm` сейчас переводит любой `VetmanagerError` в `ToolError` и код `INTERNAL_ERROR` может обобщить; поэтому для узкого вызова `/data` нужен opt-in путь, сохраняющий оригинальное исключение только при HTTP 500/`INTERNAL_ERROR` после учёта метрик. `get_report_ai_job_data` добавляет безопасную подсказку, сохраняя тип исключения и HTTP/code. `feedback_safe_excerpt` получает фиксированный текст с `INTERNAL_ERROR`/HTTP 500, без доверия сообщению ВМ. Исторический fingerprint меняется; настроенное правило KI 60 использует match rules, а не точный старый fingerprint, и проверяется на новом incident через зарегистрированный инструмент. Публичные описания живут в `tool_descriptions.py` и общем файле prompt-helper.

Рассмотрены: (1) только match rules KI — не видят удалённый SQL и не предотвращают молчаливую ошибку остатка; (2) общий перехват 500 — даст ложные советы другим инструментам; (3) адресные классификаторы и описание — выбранный вариант с узкой областью и прежним контрактом ошибок. Инварианты: SQL и данные клиники не возвращаются; no false positive на других PREVIEW_FAILED/HTTP 500; save не повторяется автоматически; права и REST-пути не меняются. Откат: убрать новые ветки и текст, оставив прежнюю очистку SQL и конфигурацию KI. Этап меняет публичный MCP-контракт и production behavior, поэтому Architecture Critique совмещён с сильным PRD-review.

## Проверки

Фокусные тесты до и после кода; Spark → Astra и Sol xhigh на PRD/архитектуру и committed diff. Аудит, живой вызов, затем один полный mock+real suite по итоговому SHA, push и CI Tests/Deploy Prod.

## Ревью PRD и простота

Spark указал на нестрогий критерий SQL-ошибки; принят и уточнён в приёмке. Astra указала на сохранение fingerprint KI 60; первоначально принято, затем пересмотрено после committed diff review: сохранение произвольного excerpt опасно для приватности. Sol указал на преобразование исходного исключения внутри `_call_vm`, перекрытие good.id и default `clinic_id=1`; все три замечания приняты. Замечания Astra/Sol о Claude Opus отклонены: прямое указание владельца для этапа 393 требует Sol xhigh и запрещает запуск Opus. После committed diff review Sol обнаружил утечку сырого HTTP 500 в feedback-диагностику (high), смену исторического fingerprint (medium) и необходимость `clinic_id` у обоих прямых инструментов (medium). Всё принято: excerpt фиксирован, match rules KI 60 проверены, clinic_id указан. Из-за изменённого решения о fingerprint проводится второй PRD/Architecture Critique. Архитектура остаётся адресной: одна ветка для PREVIEW_FAILED и одна для GET `/data`; production KI не меняется.

Повторный PRD-гейт: Spark и Astra `findings=[]`. Sol нашёл три medium: broad rule KI 60 может совпасть с иным `/data`-отказом `unknown` (существующее ограничение production-конфига, вне изменений этапа), тест не доходил до реального KI lookup (исправлено локальным аналогом правила и вызовом зарегистрированного инструмента), тест публичного ответа не запрещал сырой SQL (исправлено). Точный production JSON не снимался; форма правила взята из read-only work log супервизора. Сильный PRD-бюджет исчерпан, принятые critical/high закрыты.

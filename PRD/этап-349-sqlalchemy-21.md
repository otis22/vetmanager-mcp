# Этап 349. Переход на SQLAlchemy 2.1

## Цель

Перейти с 2.0.54 на линию SQLAlchemy 2.1 без повторения отказа запуска из этапа 348. На чистом образе должны работать асинхронный сервер и синхронные миграции PostgreSQL 16.

## Проверенные факты и границы

- Runtime использует `postgresql+asyncpg`, локальный контур — `sqlite+aiosqlite`; `storage.py` нормализует также короткие URL.
- `alembic/env.py` запускает синхронный `engine_from_config`; в образе установлен `psycopg2-binary`, а не `psycopg`.
- По постановке владельца, 25.09 два выпуска этапа 348 падали на старте нового образа именно из-за отсутствующего `greenlet` и выбора `psycopg` для Alembic. Сторож воспроизводит обе конфигурации: убранный `[asyncio]` и голый `postgresql://`.
- В SQLAlchemy 2.1 `greenlet` для asyncio устанавливается через extra `sqlalchemy[asyncio]`; `postgresql://` по умолчанию выбирает `psycopg` 3. Источник: официальные [asyncio notes](https://docs.sqlalchemy.org/en/21/orm/extensions/asyncio.html) и [migration guide](https://docs.sqlalchemy.org/en/21/changelog/migration_21.html).
- Изменений схемы БД и MCP API нет. Главный PRD и технические требования требуют стабильного HTTP MCP сервера; OpenAPI Vetmanager здесь не определяет поведение БД.

## Архитектурное решение

Проблема: неявный выбор драйвера при синхронных миграциях и отсутствие гарантии `greenlet` в чистом образе. Сохраняем `asyncpg` для runtime; `normalize_database_url_for_migrations` преобразует `postgresql+asyncpg://`, `postgresql://` и `postgres://` в **`postgresql+psycopg2://`**, уже явный `postgresql+psycopg2://` сохраняет, а `sqlite+aiosqlite:///` переводит в обычный `sqlite:///`. `alembic/env.py` использует эту функцию для online и offline режимов. Сохраняем extra `[asyncio]` в обоих источниках зависимостей. Версию ограничиваем `>=2.1,<2.2` для отдельного контролируемого обновления minor-линии.

Альтернативы: установить `psycopg` 3 и оставить неявный URL — добавляет второй драйвер и меняет поведение миграций; полностью перевести Alembic на async engine — больше изменений без пользы для текущей синхронной цепочки. Явный `psycopg2` минимален и согласован с образом.

Инварианты: миграции всегда используют синхронный `psycopg2` на PostgreSQL и обычный `sqlite` локально; runtime остаётся `asyncpg`/`aiosqlite`; greenlet присутствует в чистой установке; история миграций не меняется.

Rollback: если новый образ не проходит миграции или health в Deploy Prod, вернуть оба ограничения к `<2.1` **и изменить версионную часть сторожа обратно на 2.0**, сохранив проверки `[asyncio]` и явного `psycopg2` URL; заново собрать и выпустить штатным CI. Данные не откатывать, поскольку DDL этого этапа нет. Новый образ не принимать без зелёного Deploy Prod. Прямые подключения к production не использовать.

## Подзадачи

1. Заменить старый сторож версии на проверку зависимости `[asyncio]`, установленной 2.1, синхронного драйвера и контура Alembic; показать красный результат на старой конфигурации. До 150 строк.
2. Исправить оба источника зависимостей и нормализацию URL; пройти фокусные тесты. До 150 строк.
3. Собрать production и test образы с `--no-cache`; на отдельном PostgreSQL 16 тестового контура применить миграции и запустить приложение; затем один полный mock и real suite. До двух часов.
4. Аудит, committed diff review, штатный push в main и зелёные Tests/Deploy Prod; при отказе выпуска — rollback тем же этапом. До двух часов.

## Критерии приёмки

- Чистый production образ импортирует `greenlet`, запускает сервер и выполняет `alembic upgrade head` на изолированном PostgreSQL 16: сначала создаёт копию предыдущей схемы из цепочки миграций до ревизии `20260924_000025`, добавляет синтетическую строку без пользовательских данных, затем обновляет её до текущего `head` (`20261002_000026`) и проверяет сохранность строки; отдельно проверяется создание с нуля.
- Сторож реально краснеет при утрате extra `[asyncio]`, неявном PostgreSQL драйвере и выходе версии из линии 2.1.
- Полный mock и opt-in real suite проходят на 2.1.
- Кодовый SHA выпущен зелёным Tests и Deploy Prod или документирован честный откат к 2.0.

## Простота

Меняются два объявления зависимости и одна функция нормализации. Нового слоя конфигурации и новой миграции нет. При смене драйвера достаточно одного явно указанного места.

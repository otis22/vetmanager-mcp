# Этапы 238 и 242. Инструментальная гигиена

## Цель

Сделать ошибку неполного wheel allowlist понятной и локально блокируемой до
push, а диагностический lookup streamable-HTTP session manager безопасным для
production error tracking. Сохранить ERROR для настоящего runtime-отказа
слива. Проверить остальные ERROR runtime-логгера на штатные пути.

## Проверенные факты и ограничения

- `tests/test_packaging_metadata.py` сравнивает корневые `*.py` с
  `tool.hatch.build.targets.wheel.only-include` из `pyproject.toml`; до этой
  задачи два bare `assert` не показывают разницу.
- Локальные workflow-гейты уже распространяются opt-in скриптом
  `scripts/install_git_hooks.sh`, который создаёт `commit-msg` и `pre-commit`.
  Docker Compose — обязательный способ запуска тестов в проекте.
- `_get_streamable_session_manager` используется и диагностическими пробниками,
  и shutdown runtime-путём. После lifespan manager присутствует; без lifespan
  его отсутствие — ожидаемый результат диагностики.
- HTTP transport и контракты Claude/ChatGPT не меняются. Production, DSN и
  настройки Sentry не затрагиваются; секреты не логируются.

## Архитектурное решение

### Проблема

Новый корневой runtime-модуль легко не включить в wheel, а bare assertion
обнаруживает это только CI. Общая функция lookup manager-а сейчас не отличает
вызов-инспекцию без lifespan от shutdown runtime-пути и сама пишет ERROR.

### Варианты

1. Полный test suite в pre-push. Надёжно, но медленно и дублирует CI, поэтому
   ухудшает локальный цикл.
2. Отдельный host-Python скрипт. Быстро, но нарушает принятый container-only
   запуск и зависит от окружения разработчика.
3. Узкий packaging-тест через существующий installer pre-push hook. Проверяет
   ровно инвариант allowlist, запускается одинаково в Docker и естественно
   продолжает текущие локальные гейты.

Выбран вариант 3. Installer остаётся opt-in, как и существующие hooks; это
сохраняет текущую модель clone/setup и делает проверку доступной до push.

Для lookup добавляется явный флаг `report_missing=False`: прямой
диагностический пробник сохраняет безопасное поведение без дополнительного
аргумента и возвращает `None` без ERROR, а единственный runtime shutdown путь
явно передаёт `True`. Ошибка поиска и недоступная структура drain на реальном
shutdown остаются ERROR.

### Инварианты

- Ошибка allowlist называет каждый отсутствующий модуль и `pyproject.toml`.
- Установленный pre-push блокирует push при падении packaging-теста; запускает
  контейнер без TTY и с отсоединённым stdin, поэтому не захватывает ref-list,
  который Git передаёт hook-у.
- Диагностический lookup без lifespan не создаёт ERROR/event.
- Runtime shutdown при отсутствии manager-а по-прежнему создаёт ERROR/event;
  успешный drain и transport contract не меняются.
- Другие найденные ERROR остаются, если означают аномалию: strict Redis failure,
  неверный внутренний event name или HTTP 500 custom route.

### Rollback/fallback

Перед заменой уже существующего `pre-push` installer сохраняет timestamped
backup рядом с ним; при проблемах его можно восстановить либо удалить hooks
стандартной командой uninstall из installer. Если Docker недоступен, hook
завершается с ошибкой и не даёт ложно-зелёный push; CI packaging-test остаётся
последней защитой. Если upstream FastMCP изменит структуру session manager,
runtime ERROR останется сигналом и kill switch drain отключит lookup.

Architecture Critique: not required — изменения не меняют public/API/MCP
contract, auth, storage, внешние интеграции либо границы ownership.

## Acceptance criteria

1. При отсутствующем root module packaging-test пишет имена модулей и указание
   добавить их в `pyproject.toml`.
2. После `scripts/install_git_hooks.sh` созданный `pre-push` запускает только
   `tests/test_packaging_metadata.py` через Docker Compose с `-T` и
   `/dev/null`; существующий `pre-push` предварительно backup-ится.
3. Lookup manager-а без lifespan по умолчанию не логирует ERROR; runtime
   shutdown явно запрашивает ERROR и при `None` логирует
   `streamable_http_drain_unsupported` на ERROR.
4. Все текущие runtime ERROR классифицированы: исправлен ложный diagnostic
   path, остальные подтверждены как аварийные.
5. Focused и полный Docker tests, ShellCheck/bash syntax, audit, Spark и Claude
   code-review, push и зелёный PR завершены.

## Вне scope

- Изменение production server, Sentry project/alerts/DSN, FastMCP transport и
  контрактов Claude/ChatGPT.
- Автоматическая установка hooks либо новый runtime module.

# Этап 442 — формат списков и отказ Report AI

## Цель и границы

Агент, передавший CSV в `fields`, получает ошибку со способом исправления. Голый HTTP 403 от Report AI объясняет отказ доступа. CSV не разбирается автоматически. Успешные вызовы и ошибки с явным неизвестным кодом сохраняют поведение.

## Проверенные факты

- `fields` добавляется к `get_admissions`, `get_invoices`, `get_clients` в `identifier_aliases.canonical_tool`, а не объявлен в `tools/admission.py`. Канонические поля берутся из `list_projection.LIST_FIELDS`.
- `fields`, `include`, raw `filter`/`sort`, `diagnosis_ids`, `params_shape` используют семейство `OptionalJsonList` из `filters.py`. Строка проходит через Pydantic BeforeValidator до тела инструмента; `ValueError` превращается в ValidationError FastMCP.
- `vetmanager_client._raise_for_status` создаёт `AuthError` с HTTP 403 без `error_code` для отказа `report-ai-job`; наблюдаемый код хранится отдельно. HTTP 401 тоже создаёт `AuthError`, но он уже имеет смысл ошибки ключа. Для этого этапа 401 не меняется.
- Справочник `artifacts/api_entity_reference-ru.md` описывает admission и `client_id`; допустимые имена проекции заданы локальным контрактом `LIST_FIELDS`, потому что это проекция ответа MCP, не параметр REST API.

## Архитектурное решение

Проблема: Pydantic отклоняет строку раньше текущей проверки проекции и выдаёт техническую ошибку. Вариант локальной проверки `selected_fields` не достигается. Вариант молча разбирать CSV меняет смысл запроса и запрещён владельцем. Выбран специализированный BeforeValidator для `fields` с `ToolInputError` и примером `fields: ["id", "client_id", "pet_id"]`; общий валидатор списков получает содержательные примеры по типу списка. Схема инструмента остаётся массивом. Красный/зелёный MCP-тест подтвердил фактический тип исключения на границе FastMCP: Pydantic пропускает не-`ValueError` исключение валидатора, FastMCP сохраняет текст. Если обновление FastMCP сломает этот контракт, запасной вариант — принимать `list[str] | str` в адаптере и проверять строку внутри `canonical_tool` до I/O. Для Report AI маппинг применяется лишь к HTTP 403 без машинного кода. Существующий `vetmanager_client._raise_for_status` записывает непустой `data.error_code` в `observed_error_code` на `AuthError`; пустой или `null` код считается отсутствующим. Маппер использует HTTP-статус только при отсутствии этого кода. Явные коды и неизвестные HTTP-статусы сохраняются.

Инварианты: JSON-массивы и совместимая JSON-строка массива проходят; любая строка, не декодируемая в JSON-массив (`id`, `id,client_id`, `"id"`, пустая строка), отклоняется; строка `[]` декодируется, затем проверяется правилом непустой проекции. Неизвестный явный код не выдаётся наружу; отказ локального scope сохраняет свою подсказку; никакой сырой текст ВМ не отражается. Rollback: вернуть validator alias и ветку маппинга одним коммитом при несовместимости с FastMCP.

Architecture Critique требуется: изменяется публичный MCP-контракт ошибок и классификация upstream-отказа. Сильный PRD-гейт покрывает архитектуру и критерии приёмки одновременно.

## Подзадачи

1. 442.1 (≤ 2 ч): сторожа CSV для трёх инструментов проекции, raw filter и валидного массива; сторож голого HTTP 403; показать red.
2. 442.2 (≤ 150 строк): валидаторы и маппинг, green, аудит и релизный поезд.

## Приёмка

- `get_admissions(fields="id,client_id")` сообщает тип полученного значения, ожидаемый JSON-массив и рабочий пример из канонических полей.
- `get_invoices` и `get_clients` получают соответствующие примеры; raw filter и sort получают структуру объекта; `include` и другие пользователи общего валидатора получают ошибку с примером массива.
- Голый HTTP 403 Report AI даёт `Report AI request failed (FORBIDDEN). Check access to Report AI with the clinic administrator.`; явный неизвестный код остаётся `unknown`.
- Фокусные тесты, полный mock suite и проверка Roadmap проходят в Docker/предписанном контуре.

# Этап 397. Инструмент «кто я»

## Цель и проверенные факты

Агенту нужен явный ответ о текущем токене: домен клиники, его группа и фактические права, сводка чтения/изменения/удаления, лимит запросов. `RuntimeCredentials` уже содержит валидированный домен и эффективные scopes; `access_summary.summarize_access` строит три строки из этих scopes. `tool_access_registry` хранит группы, их права и правило допуска инструмента. `auth.rate_limit` содержит действующие лимиты запросов bearer и OAuth grant. Инструмент не требует API Vetmanager; контракт OpenAPI здесь не применяется.

## Контракт и критерии приёмки

Имя MCP-инструмента `whoami`, без аргументов. Ответ: `clinic_domain` (только валидированный домен клиники), `groups` (название одной точной группы из действующей матрицы либо пустой список для нестандартного набора scopes), `scopes` (отсортированные эффективные права токена), `access_summary` (ключи «Чтение», «Изменение», «Удаление» из `summarize_access`; «Удаление: нет» явно при отсутствии права удаления, иначе перечисляются объекты удаления), `limits` (`requests`, `window_seconds`, `subject` = `token` для bearer или `oauth_grant` для OAuth). Остаток лимита не обещается. Никаких raw токенов, ключей, внутренних адресов, аккаунтных идентификаторов и данных клиники. При пустых scopes инструмент недоступен тем же правилом, что и каталог; при невалидном токене штатный отказ авторизации.

В реестре инструмент имеет явную запись с пустым набором scopes и включён в поимённый baseline allowlist. Это минимально необходимое право: любой уже авторизованный токен с непустыми scopes может узнать свои права, но не получает доступ к данным клиники. `groups` отражает точное совпадение эффективных scopes с группой через `infer_token_preset`; пересечение или приблизительное совпадение не называется группой. Домен берётся только из проверенных runtime credentials. Имена `clinic_domain`, `scopes`, `access_summary` и `limits` являются новыми публичными именами; существующие ID инструменты и алиасы этапа 395 не меняются.

## Архитектурное решение

Один инструмент в `tools/`, зарегистрированный обычной обёрткой. Она уже проверяет авторизацию и scopes, затем кладёт credentials в request context. Тело инструмента использует эти credentials и чистые существующие функции. Отдельной БД, запроса к Vetmanager и второй матрицы групп нет. Граница ответственности: `tool_access_registry` определяет группу и допуск; `access_summary` объясняет права; `auth.rate_limit` задаёт действующий лимит. Стоимость O(число scopes), без новой внешней нагрузки.

Альтернатива `reference.read` исключила бы самые узкие токены из самодиагностики. Альтернатива списку групп, чей набор scopes содержится в токене, ошибочно назвала бы full access множеством групп. Альтернатива чтению названия preset из БД расходилась бы с эффективными OAuth scopes. Выбран точный вывод группы из эффективных прав.

Инварианты: каталог и вызов используют одинаковый допуск; ответ не содержит секретов; `summarize_access` единственный источник текста сводки; для OAuth показываются именно эффективные scopes; лимиты обозначают конфигурацию, не остаток квоты. Откат при неверном контракте — снять регистрацию и запись в реестре одним коммитом с повтором сторожей и CI; уже опубликованный контракт требует объявления потребителям перед удалением.

Architecture Critique совмещается с сильным PRD-review, поскольку затронуты auth и публичный MCP-контракт.

## Декомпозиция

1. Контрактные сторожа (≤ 2 ч): регистрация, допуск, точная группа, три строки, лимиты, отсутствие секретов, отсутствие upstream вызова. Показать красный результат до реализации.
2. Реализация инструмента и регистрация (≤ 150 строк).
3. Живой вызов на заранее выбранном `.env`-контуре под токенами `read_only` и `frontdesk`; сохранить лишь HTTP-код и безопасную форму ответа (≤ 2 ч).
4. Spark → Astra и Sol для PRD и committed diff, аудит, фокусные проверки, один полный mock+real suite по финальному кодовому SHA, push и CI (≤ 2 ч на гейт; при необходимости отдельный ход).

## Простота

Достаточно одного нового `tools`-модуля и двух записей регистрации. Новых разрешений и схем хранения нет.

## Ревью PRD и проверка решения

Spark прочёл PRD, сторожа и пять связанных модулей. Замечание о слабой проверке удаления принято: для `read_only` сторож требует точное «нет». Astra и Sol xhigh дали валидные verdict. Оба указали на отсутствие проверки реальной MCP-регистрации и вызова — добавлен сторож через `mcp.list_tools` и `mcp.call_tool`. Astra указала на неточные проверки группы и лимитов — тесты требуют точную группу и настройки окружения. Sol уточнил формулировку удаления — исправлено: «нет» только без права удаления. Замечание Sol об Opus отклонено по прямому указанию владельца этапа. После этих уточнений архитектура и публичный ответ не менялись; повтор сильной пары не нужен. Открытых high/critical нет.

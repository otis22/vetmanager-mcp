# Этап 315. Жалоба человека через агента

## Цель

Если человек прямо говорит агенту, что ответ неверен или просит передать
жалобу разработчикам, агент сохраняет краткий безопасный пересказ как feedback
с источником `human`, а не как собственный отчёт модели.

## Scope

1. Добавить `human` в единый допустимый набор feedback sources и в check
   constraint новой базы. В startup migration через каталог находит прежний
   source CHECK, терпит его отсутствие и заменяет найденный constraint на
   вариант с `human`; данные не переписываются, история model/auto остаётся
   допустимой.
2. Публичный `report_problem(..., source="model")` принимает только
   `model`/`human`; default сохраняет старое поведение. Внутренний `auto`
   остаётся отдельным существующим путём. Для human совпадение known issue
   пишется как подсказка/связь, но status остаётся `new`.
3. Инструкции initialize, special description и docstring требуют вызвать
   инструмент от имени человека при явной жалобе и запрещают дословный текст,
   имена, телефоны и сырые данные.
4. Triage `recent` и списки показывают source, `recent --source human`
   фильтрует человеческие записи. `human` означает, что агент заявил о прямой
   жалобе человека; это не верифицированная личность и triage не повышает ему
   приоритет только по этому признаку.

## Не входит

Форма кабинета (этап 316), отправка писем, изменение правила маскирования или
снятие существующих `model`/`auto` источников.

## Приёмка

- Человеческий report через MCP имеет `source=human` и `status=new`, включая
  match с known issue; модельный default остаётся `model`.
- Сторож ломается удалением `human` из allow-list либо переводом matched human
  в `linked`.
- Тест сохраняет human complaint с телефоном/фамилией и подтверждает, что в БД
  остаётся результат существующего sanitizer, а не исходный текст.
- TEST_DOMAIN вызов показывает `feedback_saved` и ID без клиентских данных;
  после выката production тестовая запись закрыта штатным `resolve-report`.
- Migration test начинает с прежнего source constraint и подтверждает insert
  human после обновления без изменения существующих model/auto строк, включая
  отсутствующий либо иначе названный прежний constraint.

## Простота

Используется существующий feedback pipeline и sanitizer: один параметр и одна
ветка статуса вместо отдельной таблицы, webhook или нового процесса triage.

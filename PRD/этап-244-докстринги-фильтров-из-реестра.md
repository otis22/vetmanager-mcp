# Этап 244. Докстринги list-инструментов и реестр фильтров

## Цель

Не давать модели фильтры, которые локальный реестр отклоняет.

## Проверенные факты и декомпозиция

`get_users` обещал удалённый зарплатный `calc_percents`, которого нет в `FILTER_FIELDS_BY_ENTITY['user']`. Список для users генерируется из реестра при построении docstring; тест AST проверяет каждый `crud_list(... allowed_filter_properties=FILTER_FIELDS_BY_ENTITY[...])` с documented `Allowed properties` в обе стороны. Проверяется отсутствие пяти вырезанных credential/payroll полей.

## Архитектурное решение

Для затронутого user-инструмента описание строится из реестра, который уже служит runtime source of truth. Полная миграция всех старых docstrings не нужна, пока проверка защищает обе стороны. Инвариант: документированный набор идентичен реестру. Architecture Critique: required (public MCP contract).

## Критерии готовности

`calc_percents` не рекламируется; тест падает на добавленном/удалённом поле у любого зарегистрированного list-инструмента.

# Этап 341. Первый запрос после выпуска ключа

## Проблема

По когортному срезу 23.09.2026 из 26 аккаунтов с ключом пять не отправили ни одного запроса, включая неуспешную авторизацию. Все пятеро копировали токен; значит после выдачи ключа нужен конкретный следующий шаг и образец полезного ответа.

## Цель

Показать следующий шаг рядом с настройкой клиента и измерить показ и копирование примера, сохранив простой экран.

## Проверенные источники и ограничения

- `Roadmap.md` §341 и read-only когортный анализ `LiveHelperAgent/workspace/2026-09-23/mcp-cohort-activation.md`: первый запрос означает первый успешный вход в журнале авторизации; у пятерых застрявших нет даже отказа.
- `artifacts/prd-vetmanager-mcp-ru.md` §4.2 и `artifacts/technical-requirements-vetmanager-mcp-ru.md` §3.1: web кабинет использует сессию; токен показывается однократно. Контракт MCP/API не меняется.
- `landing_page.py` содержит публичную секцию `#examples`; `web_html.py` — однократную панель `issued-token-panel`, ожидание с polling и `client-connect`.
- `web_routes_account.py` уже имеет защищённый CSRF endpoint копирования; `activation_events.py`, `storage_models.py` и миграция 18 ограничивают имена событий и значения меток.
- Примеры — только вымышленные; публичная страница остаётся без рекламной строки и без данных реальных клиник.

Шестая — вариант вопроса о свободном времени врачей из того же сценария, без заявления о дословной формулировке пилота.

6. 341.7 (≤2 ч): матрица локальных скриншотов лендинга и кабинета в светлой/тёмной теме, на десктопе/телефоне, для `needs_token`, `needs_client_use`, `ready`; сильное визуальное ревью с фиксацией решений.

## Архитектурное решение

**Проблема.** Нужно связать показ подсказки и копирование вопроса с аккаунтом без изменения MCP контракта и без утечки клинического текста.

**Варианты.** (1) Только счётчик в браузере: прост, но теряется после обновления и не связывается с воронкой. (2) Передавать текст вопроса на сервер: не нужен для измерения и создаёт лишний риск. (3) Добавить два фиксированных имени в существующую `activation_events`, используя CSRF route и закрытые множества значений: сохраняет существующую схему аналитики, требует миграции check constraint. Выбран вариант 3.

**Граница ответственности.** Браузер сообщает только видимый блок или успешное копирование. Сервер сверяет сессию/CSRF, сам определяет auth mode из активного подключения, передаёт bounded event в существующий best-effort writer. Отказ телеметрии не мешает копированию и работе кабинета. Дедупликация показа на странице предотвращает повтор от прокрутки; новый просмотр страницы остаётся отдельным событием. Сырые значения в event/лог не записываются. Миграция расширяет check constraint; downgrade возвращает старый набор после удаления новых строк.

**Инварианты.** Сырой токен остаётся только в однократной панели; вопросы не включают реальные данные; нет платёжной строки на лендинге; в кабинете две пары, на лендинге шесть; существующие copy endpoints и polling сохраняются; метки аналитики ограничены allowlist; реклама видна только в кабинете.

**Rollback.** Код UI и route можно откатить без потери старых событий; downgrade БД удаляет только события новых типов перед восстановлением прежнего constraint. Если браузер не поддерживает IntersectionObserver/clipboard, текст подсказки остаётся виден и доступен для ручного копирования; отсутствие telemetry не блокирует сценарий.

## Приёмка и проверки

- Красные до реализации сторожа на шесть пар и подпись лендинга, две пары/порядок ключа и инструкции в кабинете, отсутствие строки оплаты на лендинге, тексты ожидания/OAuth guide, CSRF и приватность событий, корректный `auth_mode`.
- Фокусные тесты UI, telemetry и миграции зелёные; `check_roadmap_structure.py` проходит.
- Визуальный гейт: в каждом из трёх состояний кабинета на 1440×900px и 390×844px в двух темах виден следующий шаг; сразу после выпуска ключа при автопрокрутке к началу панели короткий следующий шаг виден **без ручной прокрутки**, а ключ и конфиг не вытеснены подсказками. Проверять viewport-снимок, не только полный снимок страницы. Лендинг проверяется в тех же двух размерах и темах. Скриншоты и вывод Astra/Opus — вне working copy.
- Один полный mock и real suite перед push; затем зелёные Tests и Deploy Prod, без прямых обращений к production со стороны агента.

## Не входит

Письма, push, OAuth consent, изменение потока подключения, изменение контрактов MCP инструментов, реальные ответы клиник, публичная реклама оплаты подписок.

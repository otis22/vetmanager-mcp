## Подробности и исправления

### SR360-1 — privacy-regression (high)

- **Место:** `phone_redaction.py:14-32`.
- **Сбой:** The shared matcher omits unprefixed ten-digit 3/3/2/2 numbers separated by spaces or dots, including after an explicit telephone label.
- **Последствие:** Numbers previously matched by the free-text sanitizer can now pass into depersonalized tool responses and CSV cells. The tests cover the hyphenated form but miss these forms.
- **Исправление:** Recognize the spaced and dotted national forms in telephone context; retain the clinical-number exclusions and test both sanitization paths.
- **Доказательства:** `phone_redaction.py:14-32`; `depersonalization.py:471-478,634-649`; `report_export.py:298-304`; `tests/test_stage330_phone_redaction.py`.

### SR360-2 — stale-cache-write-guard (high)

- **Место:** `tools/warehouse.py:656-671`.
- **Сбой:** The expected_price check reads goodSaleParam without fresh=True, so it can compare against a cached price after an upstream change.
- **Последствие:** A confirmed write can pass the guard using an old price and overwrite the newer price. The entity uses the 900-second cache tier.
- **Исправление:** Make the guard read fresh data and test a primed cache followed by an upstream price change, asserting that no PUT is sent.
- **Доказательства:** `tools/warehouse.py:656-671`; `tools/crud_helpers.py:184-190`; `vetmanager_client.py:380-391,563-567`; `vm_transport/cache_policy.py:10-28`; `tests/test_stage322_repricing_recovery.py`.

### SR360-3 — cross-module-pagination-contract (medium)

- **Место:** `tools/invoice.py:464-476`.
- **Сбой:** get_average_invoice permits 1000 pages, but paginate_all uses a query builder that rejects offsets above 10000. A selection of exactly 10100 invoices needs the rejected offset=10100 request to establish completion.
- **Последствие:** Annual totals for a clinic with about 30 invoices per day fail well before the advertised page budget. The existing 10001-row test stops on a short page and misses the boundary.
- **Исправление:** Give bounded internal scans pagination beyond the public offset cap, or use keyset pagination. Cover 10100 and larger selections through the real query builder.
- **Доказательства:** `tools/invoice.py:464-478`; `tools/crud_helpers.py:268-282,307-325`; `filters.py:328-347`; `validators.py:13-18,48-60`; `tests/test_revenue_summary.py:505-533`.

### SR360-4 — authentication-instructions (medium)

- **Место:** `landing_page.py:2109-2122`.
- **Сбой:** The FAQ offers a Vetmanager REST key for resolution, then names MCP get_*_by_id tools as the lookup method. Those tools require a service bearer token; the REST key cannot authenticate their calls.
- **Последствие:** A resolver following the documented REST-key option fails at lookup.
- **Исправление:** Describe direct Vetmanager REST GET requests for that option and keep MCP tool names with the separate bearer-authenticated connection option.
- **Доказательства:** `landing_page.py:2109-2122`; `runtime_auth.py:110-135`; `server.py:227-233`.

### SR360-5 — resolver-scope-contract (medium)

- **Место:** `landing_page.py:2119-2125,2138`.
- **Сбой:** The FAQ says the assistant can prepare the described resolver, which includes pet and contact fields. Its agent instruction permits generated resolver scripts only for approved client/user IDs and name fields.
- **Последствие:** The promised assistant-generated script cannot follow both instructions; pet and contact placeholders must remain unresolved under the current agent contract.
- **Исправление:** Separate the external application's broader resolution capabilities from what the assistant may generate, or explicitly revise the agent contract after validating those fields.
- **Доказательства:** `landing_page.py:2119-2125,2138`; `placeholder_resolution_guidance.py:13-33`; `PRD/этап-360-faq-обезличивание.md:9-16`.

### SR360-6 — metrics-coverage (medium)

- **Место:** `tools/report_ai.py:693-700,1253-1256,1272-1275,1313-1316`.
- **Сбой:** A failed job returned in a successful confirm, reject, or save response updates lifecycle metrics but does not record its error code. A later status poll may also miss the code because the first observation finalizes the job key.
- **Последствие:** If the caller stops after the failed response, the failure is absent from vetmanager_report_ai_outcomes_by_code_total. An existing reject test supplies such a response but checks only SQL redaction.
- **Исправление:** Record a bounded error code on the first failed-job observation, with job-key deduplication across tool responses and later polls.
- **Доказательства:** `tools/report_ai.py:693-700,1253-1256,1272-1275,1313-1316`; `service_metrics.py:74-81,457-465`; `tests/test_stage350_report_ai_contract.py:215-227`.

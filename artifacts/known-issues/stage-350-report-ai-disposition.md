# Решение по известным проблемам Report AI после релиза 18.09

Дата: 25.09.2026. Основание: новый внешний контракт из постановки этапа 350,
живые проверки devtr6, версионированный seed и последний доступный в репо
production-снимок от 19.09 (KI-45 и KI-55). Свежий production-снимок
`show-known-issue-config`/`show` не предоставлен. Прямое чтение и запись
production DB запрещены. Это письменное решение; фактический статус записей
в production должен сверить и применить супервизор после read-only снимка.

| Запись | Решение | Причина и новое описание |
| --- | --- | --- |
| KI-45 «отчёт не экспортируется по REST» | Обновить: оставить постоянный `REPORT_NOT_ALLOWED_FOR_REST`; убрать временные busy/rate и ожидание файла из этой причины. | Новые `CONSTRUCTOR_BUSY`, `RUN_RATE_LIMITED`, `FILE_BUILD_NOT_STARTED`, `FILE_NOT_READY` требуют ожидания с разными действиями. Общее правило KI-45 и его старый playbook смешивают постоянный отказ и временные состояния. |
| KI-55 «Report export file download is unauthorized» | Закрыть как исправленную старую ветку после проверки отсутствия legacy 401 на текущем production-контуре; для новых 409/422 её не применять. | Новый `reportFile` даёт 409 `FILE_BUILD_NOT_STARTED`/`FILE_NOT_READY` и 422 `FILE_BUILD_FAILED`, а не прежний 401. |
| `report-ai-save-needs-confirmation` | Обновить playbook: если кандидат совпал по фильтрам, периоду и группировке, подтвердить; если нет — `reject_report_ai_job_candidate` один раз и ждать то же задание. | Старый текст требует подтверждать кандидата, даже когда подходящего нет. |
| `report-ai-goods-good-id-preview` | Оставить узкой legacy-проблемой до отдельного подтверждения исчезновения. | Новый релиз не утверждает, что этот edge case исправлен. |

Порядок применения: супервизор снимает свежий read-only snapshot каждой
затрагиваемой записи, сверяет фактические поля и связи, затем применяет
адресное изменение и проверяет matcher на кодах/старых текстах. `seed` не
применять поверх существующих KI при `would_update` без отдельного решения;
текущие файлы этапа 332 сохраняют историю действовавших правил. Ни один
production-сервер или DB при составлении решения не вызывался.
